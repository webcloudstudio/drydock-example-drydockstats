# ARCHITECTURE: DrydockStats

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Package layout, boundaries and pipeline of the ddkstat command-line reporter for Drydock's LLM execution log. |
| Depends On  | None |
| Provides    | go.mod, internal/, cmd/ddkstat/, bin/ |
| Consumes    | None |

## Questions

- None.

## Purpose

ddkstat reads a JSON Lines log (`logs/llm.jsonl`) and writes one of six CSV reports to standard output. It is a single-process, single-threaded CLI. It has no database, no network access and no configuration files. It never writes to the log it reads.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`:

| Technology | Where it applies |
|---|---|
| Go 1.22 or newer, standard library only | All application code under `cmd/` and `internal/`. |
| go test and go vet | Test runner behind `bin/test.sh`; tests live beside the code in `*_test.go`. |
| JSON Lines | Input format, decoded with `encoding/json`, one object per physical line. |
| POSIX sh | `bin/test.sh` and the supplied grader `sources/run.sh`. |

No third-party module is permitted. `go.mod` declares the module `ddkstat`, a `go` directive of 1.22 or newer, and no `require` lines.

## Layout

```text
go.mod                    module ddkstat
cmd/ddkstat/main.go       package main; the only caller of os.Exit
internal/logread/         read, validate, dedupe and normalize log records
internal/filter/          pure record filters (target, date range)
internal/format/          minutes and cost text formatting
internal/report/          one aggregate-and-write function per report
internal/cli/             Run, argument parsing, report registry
bin/test.sh               go vet ./... then go test ./...
sources/                  read-only scoring assets; never touched by application code
```

## Module Ownership

| Module | Owns | May access |
|---|---|---|
| `internal/logread` | Opening-agnostic reading of an `io.Reader`, line classification, skip and duplicate rules, numeric normalization, model attribution | `encoding/json`, `bufio`, `io`, `strings` |
| `internal/filter` | Target and date-range predicates over `[]logread.Record` | `logread` types only |
| `internal/format` | `Minutes` and `Cost` text | `fmt` |
| `internal/report` | Aggregation and CSV writing for each report | `logread`, `format`, `io` |
| `internal/cli` | Argument parsing, exit-code mapping, opening the log file read-only, report registry | `os`, `flag`, `time`, all internal packages |
| `cmd/ddkstat` | Process start and `os.Exit` | `internal/cli` |

Persistence, configuration files, file stores and external services: none. The log file is opened read-only by `internal/cli` and passed to `logread` as an `io.Reader`.

## Pipeline

Parse arguments, read the log, drop skipped and duplicate lines, filter, aggregate, format. Parsing, aggregating and formatting are separate functions, each unit-tested.

## Shared Types and Interfaces

`logread.Read(r io.Reader, warn io.Writer) (Result, error)` returns `Result{Records []Record, Skipped int}`. The error is non-nil only when reading from `r` fails.

`logread.Record` carries: `ExecutionID`, `StartedAt`, `Date` (first 10 characters of `StartedAt`), `Status`, `Failed`, `Command`, `Target`, `Provider`, `Model`, `InputTokens`, `CachedTokens`, `OutputTokens` (all `int64`), `CostUSD` (`float64`), `ElapsedMS` (`int64`), `ReturnCode` (`*int`, nil when null or absent) and `TimedOut` (`bool`).

`cli.Run(args []string, stdout, stderr io.Writer) int` is the single entry point; exit codes are 0 success, 1 unreadable log, 2 usage error. Report writers register with `cli.Register(name, fn)` where `fn(w io.Writer, records []logread.Record, skipped int) error`.

## Technical Decisions

- Text is compared by byte value; CSV values are written without quoting.
- A failing command writes nothing to standard output and one diagnostic line to standard error; stdout is buffered and flushed only on success.
- Diagnostics (skip warnings, usage line, errors) go to standard error and are never compared.
- No report answer, count or total is embedded in application code; every value comes from the log being read.

# FEATURE: Log Lines

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Read the JSON Lines log into records, ignoring blank lines and classifying failed calls. |
| Depends On  | ARCHITECTURE.md |
| Provides    | logread.Read, logread.Record |
| Consumes    | go.mod |

## Questions

- None.

## Purpose

Turn a JSON Lines stream into `logread.Record` values. Each non-blank UTF-8 line is one JSON object. This story establishes the reader, the `Record` type and the failed-call classification; later stories add skip rules, numeric normalization and model attribution.

## Behavior

- Read with `bufio.Reader` so no line-length limit applies.
- A line that is empty after trimming whitespace is blank: ignored, not counted, but it still advances the 1-based physical line number.
- Each object is decoded into a `Record` with `ExecutionID`, `StartedAt`, `Status`, `Command` (`job.command_name`), `Target` (`job.target`), `Provider` (`job.llm`), token counts, cost, `ElapsedMS`, `ReturnCode` (nullable) and `TimedOut`.
- `Failed` is true when `Status` is not `succeeded`.
- `Date` is the first 10 characters of `StartedAt`; `started_at` is accepted as any non-empty string with no further timestamp validation. A string shorter than 10 characters yields the whole string.

## Required Go tests

TestReadBlankLines, TestReadFailedStatus, TestReadStartDate, TestReadStartedAtNotValidated. Tests build their input as strings and call `logread.Read` with a `bytes.Buffer` warning writer.

# FEATURE: Log Skip

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Skip malformed, incomplete and duplicate log lines with a stderr warning and no effect on the exit code. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogLines.md |
| Provides    | logread.Read skip rules, logread.Result.Skipped |
| Consumes    | logread.Read |

## Questions

- None.

## Purpose

Make the reader tolerant. Bad lines are skipped and counted; they never fail the run.

## Behavior

`logread.Read` returns the kept records and `Result.Skipped`, the whole-file count of skipped lines. A line is skipped when:

- it is not a JSON object (invalid JSON, or valid JSON that is an array, string, number, boolean or null);
- any of `execution_id`, `started_at`, `status`, `job.command_name`, `job.target` is absent or not a non-empty string;
- its `execution_id` was already registered by an earlier kept line.

Further rules:

- Each skipped line writes one warning to the supplied warning writer naming its 1-based physical line number, counting blank lines.
- A skipped line does not register its `execution_id`; a malformed line therefore never causes a later line with that id to be skipped.
- The first occurrence of an `execution_id` is kept.
- Duplicate detection runs over the whole file inside `Read`, before any filter is applied elsewhere. A later repeat is skipped even when its first occurrence is later filtered out.
- Skipping never changes the exit code; `Read` returns a non-nil error only for an I/O failure.

# FEATURE: Log Numbers

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Treat absent, null or non-numeric token, cost and duration values as zero. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogSkip.md |
| Provides    | logread.Record numeric normalization |
| Consumes    | logread.Read |

## Questions

- None.

## Purpose

Aggregation sums these fields, so each record must carry a usable number even when the log omits it.

## Behavior

For `result.stats.input_tokens`, `cached_input_tokens`, `output_tokens`, `cost_usd` and `elapsed_ms`:

- absent counts as zero;
- JSON `null` counts as zero;
- a value of the wrong JSON type (for example a string or boolean) counts as zero;
- a record with no `result.stats` object at all, or no `result` object, is still a record with all five values zero.

`result.returncode` that is `null` or absent is represented as no return code (`ReturnCode` is nil). `result.timed_out` absent counts as false.

# FEATURE: Log Model

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Attribute each record to the executed model, falling back to the requested model. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogSkip.md |
| Provides    | logread.Record.Model |
| Consumes    | logread.Read |

## Questions

- None.

## Purpose

Reports group by model, and the model that actually ran is more truthful than the one requested.

## Behavior

`Record.Model` is `result.stats.model` when that value is present and a non-empty string; otherwise it is `job.model`. This covers an absent value, an empty string, a non-string value, and a record with no `result.stats` object. `job.model` that is absent yields an empty `Model`; the record is still kept.
