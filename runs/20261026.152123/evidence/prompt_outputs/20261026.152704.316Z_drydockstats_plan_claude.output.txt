# FEATURE: Value Format

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Shared text formatters for minutes (tenths of a minute) and cost (four decimal places). |
| Depends On  | ARCHITECTURE.md |
| Provides    | format.Minutes, format.Cost |
| Consumes    | go.mod |

## Questions

- None.

## Purpose

Every report that prints a minutes column or a cost column uses these two pure functions in `internal/format`, so the rounding rule lives in exactly one place.

## Behavior

- `Minutes(ms int64) string`: let `t = (ms + 3000) / 6000` using integer division. Return `t/10`, a `.`, then `t%10` (for example `95000` ms gives `1.6`, `0` gives `0.0`).
- `Cost(usd float64) string`: return `fmt.Sprintf("%.4f", usd)`, exactly four decimal places (zero gives `0.0000`).
- Both functions are pure, take no filters and read no input.

# FEATURE: Report Summary

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | The summary report: one CSV row of totals over the filtered records plus the whole-file skipped count. |
| Depends On  | FEATURE-CliExit.md, FEATURE-ValueFormat.md |
| Provides    | ddkstat summary |
| Consumes    | cli.Register, format.Minutes, format.Cost, logread.Record |

## Questions

- None.

## Purpose

`ddkstat summary [options] <log>` answers how many calls ran, how many were skipped, and what they used and cost.

## Behavior

- Header: `records,skipped,succeeded,failed,first,last,input_tokens,cached_tokens,output_tokens,cost_usd,minutes`.
- One data row over the filtered records, `\n` line endings.
- `records` is the filtered record count; `succeeded` and `failed` split it by the failed rule; token columns are sums; `cost_usd` uses `format.Cost`; `minutes` uses `format.Minutes` of the summed `elapsed_ms`.
- `skipped` is the whole-file skipped-line count and ignores every filter.
- `first` and `last` are the earliest and latest start dates of the filtered records, empty when none match.
- Aggregation (`SummaryAggregate`) and writing (`WriteSummary(w io.Writer, records []logread.Record, skipped int) error`) are separate functions in `internal/report`; `internal/cli` registers the writer as `summary` with `cli.Register`.

## Programmatic Acceptance

# FEATURE: Report Commands

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | The commands report: one CSV row per Drydock command with a TOTAL row. |
| Depends On  | FEATURE-CliExit.md, FEATURE-ValueFormat.md |
| Provides    | ddkstat commands |
| Consumes    | cli.Register, format.Minutes, logread.Record |

## Questions

- None.

## Purpose

`ddkstat commands [options] <log>` shows how often each Drydock command called an LLM and what it consumed.

## Behavior

- Header: `command,calls,failed,input_tokens,cached_tokens,output_tokens,minutes`.
- One row per `job.command_name`, ordered by calls descending, then command ascending by byte value.
- Final row `TOTAL,...` over all filtered records.
- Minutes use `format.Minutes` of the group's summed `elapsed_ms`.
- When no record matches, the output is the header and `TOTAL,0,0,0,0,0,0.0`.
- Text values are written unquoted and unescaped.
- `internal/report` holds the aggregate and write functions; `internal/cli` registers the writer as `commands`.

# FEATURE: Report Models

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | The models report: one CSV row per provider and executed-model pair with a TOTAL row. |
| Depends On  | FEATURE-CliExit.md, FEATURE-ValueFormat.md, FEATURE-LogModel.md |
| Provides    | ddkstat models |
| Consumes    | cli.Register, format.Cost, logread.Record |

## Questions

- None.

## Purpose

`ddkstat models [options] <log>` shows which providers and models ran the calls and what they consumed and cost.

## Behavior

- Header: `provider,model,calls,failed,input_tokens,cached_tokens,output_tokens,cost_usd`.
- One row per pair of provider (`job.llm`) and `Record.Model` (the executed model when present and non-empty, otherwise the requested model), ordered by provider then model ascending by byte value.
- Final row is `TOTAL,,...` with an empty model column, over all filtered records.
- Cost uses `format.Cost`. There is no minutes column.
- When no record matches, the output is the header and a TOTAL row of zeros with `0.0000` cost.
- `internal/report` holds the aggregate and write functions; `internal/cli` registers the writer as `models`.
