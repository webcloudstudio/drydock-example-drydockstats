FEATURE: Cli Exit

FieldValue
Version20261026 V1
DescriptionAssemble the ddkstat pipeline in cli.Run and map usage and read failures to exit codes 2 and 1.
Depends OnARCHITECTURE.md, FEATURE-CliDates.md, FEATURE-LogNumbers.md, FEATURE-LogModel.md, FEATURE-FilterTarget.md, FEATURE-FilterDates.md
Providescli.Run, cli.Register
Consumescli.ParseArgs, logread.Read, filter.ByTarget, filter.ByDateRange

Purpose

cli.Run is the single entry point behind cmd/ddkstat/main.go. It runs the pipeline: parse arguments, read the log, apply filters, dispatch to the registered report writer. Report stories plug in through a registry so Run never imports them.

Interface

  • func Run(args []string, stdout, stderr io.Writer) int
  • func Register(name string, fn func(w io.Writer, records []logread.Record, skipped int) error)

Rules

  1. Usage error: write one usage-summary line to stderr, nothing to stdout, return 2.
  2. Log cannot be opened or read: write one diagnostic line to stderr, nothing to stdout, return 1. The log is only

ever opened for reading.

  1. Otherwise read records (skip warnings go to stderr), apply ByTarget then ByDateRange, and call the writer

registered under the report name. skipped is the whole-file count, unaffected by filters.

  1. Report output is buffered and flushed to stdout only when the writer succeeds. A writer error writes one line to

stderr, nothing to stdout, and returns 1.

  1. A report name with no registered writer writes nothing and returns 0 until its report story lands.
  2. Skipped lines never change the exit code.
  3. Run never calls os.Exit; only cmd/ddkstat/main.go does.

User Acceptance

  • None.

Guardrails

  • Never write to the log being read.
  • A failing command writes nothing to stdout and exactly one diagnostic line to stderr.
  • Diagnostics go to stderr and are never compared by the grader.
  • Run does not import any report package; reports register themselves.
