# FEATURE: Cli Args

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Parse the report name, options, and log path of a ddkstat invocation into a validated Options value. |
| Depends On  | ARCHITECTURE.md |
| Provides    | cli.ParseArgs, cli.Options, cli.UsageError |
| Consumes    | go.mod |

## Questions

- None.

## Purpose

`internal/cli` turns the raw argument list into an `Options` value or a usage error. It performs no I/O and
never exits the process. Date value validation is owned by FEATURE-CliDates.md and layered onto this parser.

## Interface

```text
ddkstat <report> [--target <name>] [--since <YYYY-MM-DD>] [--until <YYYY-MM-DD>] <log>
```

- `type Options struct { Report, Target, Since, Until, LogPath string }`
- `func ParseArgs(args []string) (Options, error)`; every failure is a `*UsageError` (`errors.As`-detectable).
- `args` excludes the program name.

## Rules

1. The first argument is the report and must be one of `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
2. After the report come zero or more options, each of `--target`, `--since`, `--until` followed by exactly one value.
3. Exactly one log path follows; it is the last argument.
4. A repeated option takes its last value.
5. An option placed before the report name is a usage error (it is not a known report).
6. An unknown report, an unknown option, a missing option value, a missing log path, or an extra positional
   argument is a usage error.
7. Parsing uses a hand-rolled loop or a local `flag.FlagSet` with `flag.ContinueOnError`; it never touches the
   global flag set and never calls `os.Exit`.

# FEATURE: Cli Dates

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Validate --since and --until values as real YYYY-MM-DD calendar dates during argument parsing. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliArgs.md |
| Provides    | cli.ParseArgs date validation |
| Consumes    | cli.ParseArgs |

## Questions

- None.

## Purpose

A date option must be a real calendar date written `YYYY-MM-DD`. Anything else is a usage error that maps to
exit code 2 in FEATURE-CliExit.md.

## Rules

1. A value is valid only when `time.Parse("2006-01-02", v)` succeeds and the parsed time formatted with the same
   layout equals `v` exactly (rejecting shapes such as `2026-1-5`).
2. `2026-13-01` (bad month), `2026-02-30` (bad day), `2026-1-5` (wrong shape), and an empty value are usage errors.
3. A valid date passes through to `Options.Since` or `Options.Until` unchanged.
4. A missing value after `--since` or `--until` is a usage error.
5. Validation is applied while parsing, so `ParseArgs` returns the usage error before any log is opened.

# FEATURE: Filter Target

|-------------|-------|

| Depends On  | ARCHITECTURE.md, FEATURE-LogNumbers.md, FEATURE-LogModel.md |
| Provides    | filter.ByTarget |
| Consumes    | logread.Record |

## Questions

- None.

## Purpose

A pure function in `internal/filter` that narrows a record slice by Target. It performs no I/O and knows nothing
about reports; every report receives its output through the CLI pipeline.

## Interface

`func ByTarget(records []logread.Record, name string) []logread.Record`

## Rules

1. A record is kept when `Record.Target == name` exactly; comparison is case-sensitive.
2. An empty `name` means no `--target` was given and all records are returned.
3. No match returns an empty slice, never an error.
4. Input order is preserved and the input slice is not modified.

| Depends On  | ARCHITECTURE.md, FEATURE-LogNumbers.md, FEATURE-LogModel.md |

| Consumes    | logread.Record |

## Questions

- None.

## Purpose

A pure function in `internal/filter` that narrows a record slice by start date. Dates are already validated
`YYYY-MM-DD` text, so string comparison orders them correctly.

## Interface

`func ByDateRange(records []logread.Record, since, until string) []logread.Record`

## Rules

1. A record is kept when `Record.Date >= since` and `Record.Date <= until`; both bounds are inclusive.
2. An empty `since` or `until` is an unset bound and does not restrict.
3. When `since` is later than `until` the result is empty; this is not an error and the exit code stays 0.
4. Input order is preserved and the input slice is not modified.

# FEATURE: Cli Exit

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Assemble the ddkstat pipeline in cli.Run and map usage and read failures to exit codes 2 and 1. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliDates.md, FEATURE-LogNumbers.md, FEATURE-LogModel.md, FEATURE-FilterTarget.md, FEATURE-FilterDates.md |
| Provides    | cli.Run, cli.Register |
| Consumes    | cli.ParseArgs, logread.Read, filter.ByTarget, filter.ByDateRange |

## Questions

- None.

## Purpose

`cli.Run` is the single entry point behind `cmd/ddkstat/main.go`. It runs the pipeline: parse arguments, read the
log, apply filters, dispatch to the registered report writer. Report stories plug in through a registry so `Run`
never imports them.

## Interface

- `func Run(args []string, stdout, stderr io.Writer) int`
- `func Register(name string, fn func(w io.Writer, records []logread.Record, skipped int) error)`

## Rules

1. Usage error: write one usage-summary line to stderr, nothing to stdout, return 2.
2. Log cannot be opened or read: write one diagnostic line to stderr, nothing to stdout, return 1. The log is only
   ever opened for reading.
3. Otherwise read records (skip warnings go to stderr), apply `ByTarget` then `ByDateRange`, and call the writer
   registered under the report name. `skipped` is the whole-file count, unaffected by filters.
4. Report output is buffered and flushed to stdout only when the writer succeeds. A writer error writes one line to
   stderr, nothing to stdout, and returns 1.
5. A report name with no registered writer writes nothing and returns 0 until its report story lands.
6. Skipped lines never change the exit code.
7. `Run` never calls `os.Exit`; only `cmd/ddkstat/main.go` does.
