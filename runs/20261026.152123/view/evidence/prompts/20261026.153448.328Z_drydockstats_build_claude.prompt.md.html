## Foundation Contract

The published shape of this foundation. It is built before every other foundation: a web server,
a database, or a CLI is built *into* this tree, this environment, and this test runner. Carried
verbatim into `go_compact.md`.

- source_root: internal/
- test_command: go test ./...
- environment: the module declared in `go.mod`; no vendored toolchain
- dependencies: `go.mod`

```
project/
  go.mod                  # module path; the Go toolchain version
  cmd/                    # one directory per binary, each package main
  internal/               # application packages; not importable outside this module
  bin/                    # launchers; each runs the toolchain, never a vendored copy
```

Application foundations add packages under `internal/`. The generated persistence library is a
separate module at `persistence/`, linked by the root `go.mod`.

### Native application layouts and fixtures

Initialize the root `go.mod` in the language foundation before the DATABASE block.
Use `cmd/app/main.go` for process startup, `internal/cli` for CLI behavior, and
`internal/appserver` for HTTP behavior. The root application module requires
`drydock.local/persistence v0.0.0` with `replace drydock.local/persistence => ./persistence`;
the generated persistence directory owns its nested module. Run both module test suites.

For a CLI, expose `Run(args []string, stdout, stderr io.Writer) int`, use a local
`flag.FlagSet` with `flag.ContinueOnError`, and test with `bytes.Buffer`. Only main calls
`os.Exit`. For HTTP, expose `NewHandler(...) http.Handler` using `net/http.ServeMux`.
Use `httptest.NewRecorder` and `httptest.NewRequest` for handler tests, or
`httptest.NewServer` with `t.Cleanup(server.Close)` when testing a real HTTP client.
Keep business logic in application packages and persistence access in the shipped library.

### How do we execute and measure Acceptance Criteria in this language?

An Acceptance Criterion (AC) is an executable check of Blueprint-required behavior. Native tests
use `testing` in `*_test.go`; the project gate is `go test ./...`. Within the existing Blueprint
Python AC container, execute a named test through the shipped helper:

```python
from drydock_go import run_test
result = run_test("./internal/orders", "TestCreateOrder")
assert result.passed, (result.status, result.stdout, result.stderr)
```

Drydock stages this helper beside the criterion. It runs `go test -json -count=1 -run` with an
exact test name, retains output and per-test outcomes, and rejects absent/skipped tests as proof.
The enclosing AC provides identity, timeout, result storage and repair state. Compilation errors
remain distinct from assertion failures in `result.status`. Coverage and persistence observations
require explicit instrumentation per criterion; unavailable observations are unknown.

A criterion that exercises the command line runs the built executable through the same helper,
never `go run`, which reports every non-zero program exit as 1:

```python
from drydock_go import cli_runner
code, out, err = cli_runner("--top", "0", "data.csv")
assert code == 2, (code, out, err)
```

`cli_runner` builds the single `./cmd/<name>` main package once with `go build` and returns
`(exit_code, stdout, stderr)`; pass `package="./cmd/<name>"` when there are several, and `input=`
for standard input. A failed build settles the criterion as `execution-error`.

### How does this language provide the shared persistence contract?

Use the shipped module in `Rigging/languages/go/persistence/`. Drydock copies it to the Target's
`persistence/`, generates `schema.go`, `testing.go` and a schema command from `DATABASE.md`, and
links it into the existing root `go.mod` as `drydock.local/persistence`. Driver versions and sums
are shipped; SQLite uses `go-sqlite3` (a C compiler and CGO are required), PostgreSQL uses `lib/pq`.
Run `go mod download` during dependency provisioning; execution requires these modules available.

Call `persistence.OpenDatabase(ctx, dsn)`, then typed methods such as
`db.Tickets.List(ctx, persistence.TicketsListInput{Status: "open"})`. Methods return a value and
an error. Optional inputs use pointers; read results are generated structs. Undeclared operations
and unsupported field types fail explicitly. Use `OpenSession(ctx, dsn)` for native database criteria;
empty DSN selects the configured, provisioned application store. Defer its cleanup and check the
returned error: it rolls back on success and failure, never applies schema or deletes the store.
Pass the same Store to the feature. Other connections and external effects require committed,
idempotent criteria with owned records and supported cleanup. Both engines retain autocommit
outside explicit rollback scopes.

The Go library and generator are verified on SQLite and PostgreSQL. Keep application SQL inside
the library; agents write callers. The language foundation must create `go.mod` before the
DATABASE step. Python Blueprint AC containers invoke the native Go tests through `run_test`.

# ARCHITECTURE: DrydockStats

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Package layout, boundaries and pipeline of the ddkstat command-line reporter for Drydock's LLM execution log. |
| Depends On  | None |
| Provides    | go.mod, internal/, cmd/ddkstat/, bin/ |
| Consumes    | None |

## Purpose

ddkstat reads a JSON Lines log (`logs/llm.jsonl`) and writes one of six CSV reports to standard output. It is a single-process, single-threaded CLI. It has no database, no network access and no configuration files. It never writes to the log it reads.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`:

| Technology | Where it applies |
|---|---|
| Go 1.22 or newer, standard library only | All application code under `cmd/` and `internal/`. |
| go test and go vet | Test runner behind `bin/test.sh`; tests live beside the code in `*_test.go`. |
| JSON Lines | Input format, decoded with `encoding/json`, one object per physical line. |
| POSIX sh | `bin/test.sh` and the supplied grader `sources/run.sh`. |

No third-party module is permitted. `go.mod` declares the module `ddkstat`, a `go` directive of 1.22 or newer, and no `require` lines.

## Layout

```text
go.mod                    module ddkstat
cmd/ddkstat/main.go       package main; the only caller of os.Exit
internal/logread/         read, validate, dedupe and normalize log records
internal/filter/          pure record filters (target, date range)
internal/format/          minutes and cost text formatting
internal/report/          one aggregate-and-write function per report
internal/cli/             Run, argument parsing, report registry
bin/test.sh               go vet ./... then go test ./...
sources/                  read-only scoring assets; never touched by application code
```

## Module Ownership

| Module | Owns | May access |
|---|---|---|
| `internal/logread` | Opening-agnostic reading of an `io.Reader`, line classification, skip and duplicate rules, numeric normalization, model attribution | `encoding/json`, `bufio`, `io`, `strings` |
| `internal/filter` | Target and date-range predicates over `[]logread.Record` | `logread` types only |
| `internal/format` | `Minutes` and `Cost` text | `fmt` |
| `internal/report` | Aggregation and CSV writing for each report | `logread`, `format`, `io` |
| `internal/cli` | Argument parsing, exit-code mapping, opening the log file read-only, report registry | `os`, `flag`, `time`, all internal packages |
| `cmd/ddkstat` | Process start and `os.Exit` | `internal/cli` |

Persistence, configuration files, file stores and external services: none. The log file is opened read-only by `internal/cli` and passed to `logread` as an `io.Reader`.

## Pipeline

Parse arguments, read the log, drop skipped and duplicate lines, filter, aggregate, format. Parsing, aggregating and formatting are separate functions, each unit-tested.

## Shared Types and Interfaces

`logread.Read(r io.Reader, warn io.Writer) (Result, error)` returns `Result{Records []Record, Skipped int}`. The error is non-nil only when reading from `r` fails.

`logread.Record` carries: `ExecutionID`, `StartedAt`, `Date` (first 10 characters of `StartedAt`), `Status`, `Failed`, `Command`, `Target`, `Provider`, `Model`, `InputTokens`, `CachedTokens`, `OutputTokens` (all `int64`), `CostUSD` (`float64`), `ElapsedMS` (`int64`), `ReturnCode` (`*int`, nil when null or absent) and `TimedOut` (`bool`).

`cli.Run(args []string, stdout, stderr io.Writer) int` is the single entry point; exit codes are 0 success, 1 unreadable log, 2 usage error. Report writers register with `cli.Register(name, fn)` where `fn(w io.Writer, records []logread.Record, skipped int) error`.

## Technical Decisions

- Text is compared by byte value; CSV values are written without quoting.
- A failing command writes nothing to standard output and one diagnostic line to standard error; stdout is buffered and flushed only on success.
- Diagnostics (skip warnings, usage line, errors) go to standard error and are never compared.
- No report answer, count or total is embedded in application code; every value comes from the log being read.

# FEATURE: Log Lines

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Read the JSON Lines log into records, ignoring blank lines and classifying failed calls. |
| Depends On  | ARCHITECTURE.md |
| Provides    | logread.Read, logread.Record |
| Consumes    | go.mod |

## Purpose

Turn a JSON Lines stream into `logread.Record` values. Each non-blank UTF-8 line is one JSON object. This story establishes the reader, the `Record` type and the failed-call classification; later stories add skip rules, numeric normalization and model attribution.

## Behavior

- Read with `bufio.Reader` so no line-length limit applies.
- A line that is empty after trimming whitespace is blank: ignored, not counted, but it still advances the 1-based physical line number.
- Each object is decoded into a `Record` with `ExecutionID`, `StartedAt`, `Status`, `Command` (`job.command_name`), `Target` (`job.target`), `Provider` (`job.llm`), token counts, cost, `ElapsedMS`, `ReturnCode` (nullable) and `TimedOut`.
- `Failed` is true when `Status` is not `succeeded`.
- `Date` is the first 10 characters of `StartedAt`; `started_at` is accepted as any non-empty string with no further timestamp validation. A string shorter than 10 characters yields the whole string.

## Required Go tests

TestReadBlankLines, TestReadFailedStatus, TestReadStartDate, TestReadStartedAtNotValidated. Tests build their input as strings and call `logread.Read` with a `bytes.Buffer` warning writer.

# FEATURE: Cli Args

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Parse the report name, options, and log path of a ddkstat invocation into a validated Options value. |
| Depends On  | ARCHITECTURE.md |
| Provides    | cli.ParseArgs, cli.Options, cli.UsageError |
| Consumes    | go.mod |

## Purpose

`internal/cli` turns the raw argument list into an `Options` value or a usage error. It performs no I/O and
never exits the process. Date value validation is owned by FEATURE-CliDates.md and layered onto this parser.

## Interface

```text
ddkstat <report> [--target <name>] [--since <YYYY-MM-DD>] [--until <YYYY-MM-DD>] <log>
```

- `type Options struct { Report, Target, Since, Until, LogPath string }`
- `func ParseArgs(args []string) (Options, error)`; every failure is a `*UsageError` (`errors.As`-detectable).
- `args` excludes the program name.

## Rules

1. The first argument is the report and must be one of `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
2. After the report come zero or more options, each of `--target`, `--since`, `--until` followed by exactly one value.
3. Exactly one log path follows; it is the last argument.
4. A repeated option takes its last value.
5. An option placed before the report name is a usage error (it is not a known report).
6. An unknown report, an unknown option, a missing option value, a missing log path, or an extra positional
   argument is a usage error.
7. Parsing uses a hand-rolled loop or a local `flag.FlagSet` with `flag.ContinueOnError`; it never touches the
   global flag set and never calls `os.Exit`.
