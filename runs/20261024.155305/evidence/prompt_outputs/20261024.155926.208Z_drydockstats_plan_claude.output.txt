# FEATURE: Failures Report

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Produces the failures report, one CSV row per failed filtered record. |
| Depends On  | ARCHITECTURE.md, FEATURE-ReportFormat.md, FEATURE-LogModel.md, FEATURE-FilterDate.md |
| Provides    | failures report |
| Consumes    | FormatCost, WriteCSV, filtered records, model attribution |

## Questions

- None.

## Purpose

Write one row for each failed record that survives the --target, --since, and --until filters, so an operator can see which calls failed and why.

## Behavior

- Header: `started_at,target,command,model,returncode,timed_out`.
- A record is failed when `status` is not `succeeded`.
- Each row carries the record's `started_at`, `job.target`, `job.command_name`, the model from LOG-004 attribution, `result.returncode`, and `result.timed_out`.
- `returncode` is written empty when `result.returncode` is `null` or absent; otherwise its integer value.
- `timed_out` is written as the literal `true` or `false`.
- Rows are ordered by `started_at`, then `execution_id`, both ascending by byte-wise comparison.
- There is no TOTAL row.
- A filter that matches no failed record writes the header only.
- The skipped count is not part of this report.

## Programmatic Acceptance

# FEATURE: Empty-Match Report Output

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Ensures every report writes its header and, where applicable, a zero TOTAL row when no record matches. |
| Depends On  | ARCHITECTURE.md, FEATURE-ReportSummary.md, FEATURE-ReportCommands.md, FEATURE-ReportTargets.md, FEATURE-ReportModels.md, FEATURE-ReportDaily.md, FEATURE-ReportFailures.md |
| Provides    | empty-match report output |
| Consumes    | summary report, commands report, targets report, models report, daily report, failures report |

## Questions

- None.

## Purpose

When a filter matches no record, every report still produces its header, and the reports that carry a TOTAL row produce a zero TOTAL row, so the output shape never depends on whether data matched.

## Behavior

- `summary`: one data row with `records=0`, `succeeded=0`, `failed=0`, all token totals `0`, `cost_usd` `0.0000`, `minutes` `0.0`, and empty `first` and `last`. `skipped` still counts the whole file.
- `commands`, `targets`, `models`, `daily`: header followed by a TOTAL row of zeros (`0.0` minutes, `0.0000` cost where present). Models writes an empty model column in its TOTAL row.
- `failures`: header only.
- Exit code remains 0 for an empty match.

# FEATURE: Command Line Parsing

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses the report name, options, and the single log path, then dispatches to the matching report. |
| Depends On  | ARCHITECTURE.md, FEATURE-BuildEntry.md, FEATURE-FilterDate.md, FEATURE-ReportEmptyMatch.md |
| Provides    | ddkstat command line |
| Consumes    | Run, FormatCost, summary report, commands report, targets report, models report, daily report, failures report |

## Questions

- None.

## Purpose

Give the operator one invocation shape: `ddkstat <report> [--target <name>] [--since <date>] [--until <date>] <log>`.

## Behavior

- `Run(args []string, stdout, stderr io.Writer) int` uses a local `flag.FlagSet` configured with `flag.ContinueOnError`.
- The first argument is the report name and must be one of `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
- Options follow the report name. Exactly one log path is the final argument.
- `--target`, `--since`, and `--until` are passed to the filters; `--since` and `--until` are validated by the CLI before filtering.
- On a valid invocation, the matching report function is called and its exit code is returned.
- Usage-error classification is owned by FEATURE-CliUsageErrors.md; this feature only parses and dispatches.

# FEATURE: Usage Error Exit Codes

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Maps every command-line usage error to exit code 2 with no standard output. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliParse.md |
| Provides    | usage error exit 2 |
| Consumes    | Run |

## Questions

- None.

## Purpose

Let a caller distinguish a malformed invocation from an operational failure, so a wrong command is never mistaken for an unreadable log.

## Behavior

- Usage errors are: unknown report name, unknown option, missing option value, invalid `--since` or `--until` date, and a missing or extra log path.
- Each usage error returns exit code `2`, writes one diagnostic line to standard error, and writes nothing to standard output.
- A date is valid only when `time.Parse` accepts it with layout `2006-01-02`; impossible dates such as `2026-02-30` are rejected.
- Usage checks run before the log is opened.

## Programmatic Acceptance

# FEATURE: Unreadable Log Exit Code

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Maps an unopenable or unreadable log to exit code 1 with no standard output. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliParse.md, FEATURE-LogDecode.md |
| Provides    | unreadable log exit 1 |
| Consumes    | Run, log decoder |

## Questions

- None.

## Purpose

Tell the operator that the log itself could not be used, distinct from a bad invocation.

## Behavior

- When the log cannot be opened, or a read fails, `Run` returns exit code `1`.
- Exactly one diagnostic line is written to standard error.
- Nothing is written to standard output.
- The full report is built in memory and written to stdout only after the whole log has been read successfully.
