<requirement name="standard-library-go" stories="build-entry">
Implement in Go 1.22 or newer using only the standard library.
</requirement>
<requirement name="go-module-layout" stories="go-foundation">
The application root is a Go module, and its executable is the main package at `./cmd/ddkstat`.
</requirement>
<requirement name="build-executable" stories="build-entry">
The harness runs `go build -o <temporary path> ./cmd/ddkstat` and then runs 20 checks against `sources/llm_sample.jsonl`.
</requirement>
<requirement name="grader-verdict" stories="grader-gate">
`drydock uat` runs `sh sources/run.sh` from the completed application root and takes its exit code and output as the score.
</requirement>
<requirement name="go-test-suite" stories="test-runner">
Tests run under `go test`.
</requirement>
<requirement name="test-script" stories="test-runner">
The completed application provides a POSIX-compatible `bin/test.sh` that runs `go vet ./...` and `go test ./...` from the application root and exits zero only when both pass.
</requirement>
<requirement name="test-coverage" stories="test-runner">
The suite covers each report, each filter, each skip rule, and each exit code using logs written by the tests.
</requirement>
<requirement name="decode-json-lines" stories="log-decode">
The log is JSON Lines in UTF-8: one JSON object per line.
</requirement>
<requirement name="ignore-blank-lines" stories="log-decode">
**Blank lines** are ignored and not counted.
</requirement>
<requirement name="skip-invalid-lines" stories="log-decode log-required-fields log-duplicates">
A line is skipped when it is not a JSON object, when any of `execution_id`, `started_at`, `status`, `job.command_name`, or `job.target` is absent or not a non-empty string, or when its `execution_id` already appeared on an earlier line.
</requirement>
<requirement name="keep-first-occurrence" stories="log-duplicates">
The first occurrence of an `execution_id` is kept.
</requirement>
<requirement name="warn-skipped-line" stories="log-required-fields log-duplicates">
Each skipped line writes one warning to standard error naming its line number.
</requirement>
<requirement name="skip-keeps-exit-zero" stories="cli-success-partial">
Skipping never changes the exit code.
</requirement>
<requirement name="absent-numbers-zero" stories="log-numeric">
An absent or `null` token count, cost, or duration counts as zero.
</requirement>
<requirement name="stats-optional-record" stories="log-numeric">
A record with no `result.stats` object at all is still a record.
</requirement>
<requirement name="attribute-executed-model" stories="log-model">
A record's model is `result.stats.model` when present and non-empty, otherwise `job.model`.
</requirement>
<requirement name="classify-failed" stories="report-summary report-commands report-targets report-models report-daily report-failures">
A record is failed when `status` is not `succeeded`.
</requirement>
<requirement name="format-minutes" stories="report-format">
A minutes column is the group's summed `elapsed_ms` written in tenths of a minute:
</requirement>
<requirement name="format-cost" stories="report-format">
A cost column is the group's summed `cost_usd` written with exactly four decimal places, as Go's `%.4f` writes a `float64`.
</requirement>
<requirement name="byte-order" stories="report-commands report-targets report-models report-daily report-failures">
Text is compared by byte value.
</requirement>
<requirement name="filters-apply-everywhere" stories="filter-target filter-date">
Filters apply to every report.
</requirement>
<requirement name="filter-target-exact" stories="filter-target">
Keep only records whose `job.target` equals `<name>` exactly.
</requirement>
<requirement name="filter-date-range" stories="filter-date">
Keep only records whose start date is on or after `<date>`.
Keep only records whose start date is on or before `<date>`.
</requirement>
<requirement name="start-date-prefix" stories="filter-date report-daily">
Its first 10 characters are the start date.
</requirement>
<requirement name="valid-date-option" stories="cli-usage-errors">
A date option must be a real calendar date written `YYYY-MM-DD`.
</requirement>
<requirement name="argument-order" stories="cli-parse">
`<report>` comes first, options follow it, and the log path is last. Exactly one log path is required.
</requirement>
<requirement name="report-names" stories="cli-parse">
`<report>` is one of `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
</requirement>
<requirement name="csv-output" stories="report-format">
Every report writes CSV to standard output: one header row, then data rows, comma-separated, `\n` line endings.
</requirement>
<requirement name="total-row" stories="report-commands report-targets report-models report-daily">
Every report except `summary` and `failures` ends with a `TOTAL` row over all filtered records.
</requirement>
<requirement name="empty-match-output" stories="report-empty-match">
When no record matches, a report writes its header and, where it has one, a `TOTAL` row of zeros (`0.0` minutes, `0.0000` cost).
</requirement>
<requirement name="summary-row" stories="report-summary">
One row. `first` and `last` are the earliest and latest start dates, empty when no record matches.
</requirement>
<requirement name="summary-skipped-count" stories="report-summary">
The `skipped` count in `summary` counts skipped lines in the whole file regardless of filters.
</requirement>
<requirement name="commands-rows" stories="report-commands">
One per command, by calls descending, then command ascending. Then `TOTAL,…`.
</requirement>
<requirement name="targets-rows" stories="report-targets">
One per Target, by Target ascending. Then `TOTAL,…`.
</requirement>
<requirement name="models-rows" stories="report-models">
One per provider and model pair, by provider then model ascending. Then `TOTAL,,…`.
</requirement>
<requirement name="daily-rows" stories="report-daily">
One per start date, ascending. Then `TOTAL,…`.
</requirement>
<requirement name="daily-token-sum" stories="report-daily">
`tokens` is input plus cached plus output.
</requirement>
<requirement name="failures-rows" stories="report-failures">
One per failed record, by `started_at` then `execution_id` ascending.
</requirement>
<requirement name="failures-fields" stories="report-failures">
`returncode` is empty when `null` or absent. `timed_out` is `true` or `false`.
</requirement>
<requirement name="unreadable-log-exit" stories="cli-unreadable-log">
Operational failure: the log cannot be opened or read.
</requirement>
<requirement name="usage-error-exit" stories="cli-usage-errors">
Usage error: unknown report or option, missing option value, invalid date, missing or extra log path.
</requirement>
<requirement name="failing-command-output" stories="cli-unreadable-log cli-usage-errors">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="success-exit" stories="cli-success-partial">
Success, including a log with skipped lines or no matching records.
</requirement>
