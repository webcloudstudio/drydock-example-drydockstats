# FEATURE: Report Failures

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Produce the failures report: one CSV row per failed record, ordered by started_at then execution_id. |
| Depends On  | FEATURE-FilterDate.md, FEATURE-LogModel.md |
| Provides    | failures report |
| Consumes    | filtered records, record model attribution |

## Questions

- None.

## Purpose

Write the `failures` report for `ddkstat failures <log>`. Each failed record, meaning a record whose `status` is not `succeeded`, produces one data row after the header. The report has no TOTAL row.

## Output

Header:

```
started_at,target,command,model,returncode,timed_out
```

Row fields, in order:

- `started_at`: the record's `started_at` value as written in the log.
- `target`: `job.target`.
- `command`: `job.command_name`.
- `model`: the attributed model from `log-model`.
- `returncode`: `result.returncode` as a decimal integer, or empty when `null` or absent.
- `timed_out`: the literal `true` or `false` from `result.timed_out`; `false` when absent.

Ordering: by `started_at` then `execution_id`, both ascending by byte-wise comparison.

Filters from `FEATURE-FilterDate.md` and `FEATURE-FilterTarget.md` apply before rows are produced. Empty-match behavior is owned by `FEATURE-ReportEmptyMatch.md`.

## Programmatic Acceptance

=== AC failures-header-and-rows ===
Intent: The failures report writes its declared header and one row per failed record, with timed_out written as the literal true or false.
Suite: scoped

import csv
import io
import json
import os
import subprocess
import tempfile

HEADER = ["started_at", "target", "command", "model", "returncode", "timed_out"]

lines = [
    {"schema_version": 1, "execution_id": "a-1", "started_at": "2026-10-14T01:00:00.000Z",
     "status": "failed", "job": {"command_name": "build", "target": "T1", "llm": "claude", "model": "haiku"},
     "result": {"returncode": 1, "timed_out": False, "stats": {}}},
    {"schema_version": 1, "execution_id": "a-2", "started_at": "2026-10-14T02:00:00.000Z",
     "status": "succeeded", "job": {"command_name": "build", "target": "T1", "llm": "claude", "model": "haiku"},
     "result": {"returncode": 0, "timed_out": False, "stats": {}}},
    {"schema_version": 1, "execution_id": "a-3", "started_at": "2026-10-14T03:00:00.000Z",
     "status": "failed", "job": {"command_name": "diagnose", "target": "T2", "llm": "claude", "model": "sonnet"},
     "result": {"returncode": None, "timed_out": True, "stats": {"model": "claude-sonnet-5-5"}}},
]

with tempfile.TemporaryDirectory() as work:
    log = os.path.join(work, "llm.jsonl")
    with open(log, "w", encoding="utf-8") as f:
        for record in lines:
            f.write(json.dumps(record) + "\n")
    result = subprocess.run(
        [os.path.join(os.getcwd(), "ddkstat"), "failures", log],
        capture_output=True, text=True,
    )
    print(result.stdout)
    print(result.stderr)
    assert result.returncode == 0, (result.returncode, result.stderr)
    rows = list(csv.reader(io.StringIO(result.stdout)))
    assert rows[0] == HEADER, rows[0]
    assert rows[1] == ["2026-10-14T01:00:00.000Z", "T1", "build", "haiku", "1", "false"], rows[1]
    assert rows[2] == ["2026-10-14T03:00:00.000Z", "T2", "diagnose", "claude-sonnet-5-5", "", "true"], rows[2]
    assert len(rows) == 3, rows

# FEATURE: Report Empty Match

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Make every report write its header, and a zero TOTAL row where applicable, when no record matches. |
| Depends On  | FEATURE-ReportSummary.md, FEATURE-ReportCommands.md, FEATURE-ReportTargets.md, FEATURE-ReportModels.md, FEATURE-ReportDaily.md, FEATURE-ReportFailures.md |
| Provides    | empty-match report output |
| Consumes    | summary report, commands report, targets report, models report, daily report, failures report |

## Questions

- None.

## Purpose

When a filter matches no record, every report still writes its header. Reports with a TOTAL row write a zero TOTAL row. The summary report writes empty `first` and `last`. The failures report writes its header only. The `skipped` count still reflects the whole file.

## Output

- `summary`: header, then one row with `records` 0, `first` and `last` empty, token and cost totals zero, `cost_usd` `0.0000`, `minutes` `0.0`.
- `commands`, `targets`, `models`, `daily`: header, then a TOTAL row with zeros, `0.0` minutes, and `0.0000` cost where those columns exist. The models TOTAL row has an empty model column.
- `failures`: header only.

## Programmatic Acceptance

# FEATURE: CLI Parse

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parse the report name, options, and the single log path, then run the matching report. |
| Depends On  | FEATURE-BuildEntry.md, FEATURE-FilterDate.md, FEATURE-ReportEmptyMatch.md |
| Provides    | ddkstat command line |
| Consumes    | summary, commands, targets, models, daily, failures reports; --target, --since, --until filters |

## Questions

- None.

## Purpose

`ddkstat <report> [--target <name>] [--since <YYYY-MM-DD>] [--until <YYYY-MM-DD>] <log>` parses arguments, wires the filters, and writes the selected report to standard output.

## Behavior

- The first argument is the report name: one of `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
- Options follow the report name. The log path is the final argument, and exactly one is required.
- `Run(args []string, stdout, stderr io.Writer) int` uses a local `flag.FlagSet` configured with `flag.ContinueOnError`.
- Parsed `--target`, `--since`, and `--until` values are passed to the filters before the report function runs.
- Usage-error handling is owned by `FEATURE-CliUsageErrors.md`. Unreadable-log handling is owned by `FEATURE-CliUnreadableLog.md`.

# FEATURE: CLI Usage Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Map usage errors to exit code 2 with no standard output. |
| Depends On  | FEATURE-CliParse.md |
| Provides    | usage error exit 2 |
| Consumes    | ddkstat command line |

## Questions

- None.

## Purpose

Usage errors exit with code `2`, write one diagnostic line to standard error, and write nothing to standard output.

## Usage Errors

- An unknown report name.
- An unknown option.
- A missing option value.
- A missing or extra log path.
- A `--since` or `--until` value that is not a real calendar date in `YYYY-MM-DD` form. Validation uses `time.Parse` with layout `2006-01-02`, which rejects impossible dates such as `2026-02-30`.
