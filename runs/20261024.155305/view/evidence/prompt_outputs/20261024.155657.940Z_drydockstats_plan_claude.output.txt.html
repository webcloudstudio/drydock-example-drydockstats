# FEATURE: Log Model Attribution

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Attribute each decoded log record to its executed model, falling back to the requested model. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogDecode.md |
| Provides    | record model attribution |
| Consumes    | log record decoder |

## Questions

- None.

## Purpose

Each record's model is the model that actually ran. When `result.stats.model` is present and non-empty it is used; otherwise the requested model `job.model` is used. The provider is read from `job.llm`, and an absent provider is the empty string. Reports group by this attribution, so it must be computed once per record, after decoding and before aggregation.

## Behavior

- Model = `result.stats.model` when that value is a string, present, and non-empty.
- Otherwise Model = `job.model`.
- Provider = `job.llm`; when absent, the empty string.
- Implemented as a pure function over one decoded record in `internal/logrecord`, returning `(provider, model string)`.

## Programmatic Acceptance

Token counts, cost, and duration are summed by every report. A value that is absent or `null` contributes zero. A record with no `result.stats` object is still a record and contributes zero to every numeric total.

## Behavior

## Questions

- None.

## Purpose

The `--target` option narrows every report to records for one Target. The comparison is exact and case-sensitive. When the option is absent every record passes. The filter receives records only after the skip rules have run, so the whole-file `skipped` count is unaffected.

## Behavior

- With `--target X`, a record passes when `job.target == X` as a byte-exact string comparison.
- Without `--target`, every record passes.
- The filter never changes the skipped count.

# FEATURE: Start Date Filter

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Keep records whose start date falls within the inclusive --since and --until range. |
| Depends On  | ARCHITECTURE.md, FEATURE-FilterTarget.md |
| Provides    | date range filter |
| Consumes    | record stream after target filter |

## Questions

- Q-004: The source defines the start date as the first 10 characters of `started_at` but does not say what happens when that text is shorter than 10 characters or is not a date. System choice: use the first min(10, length) characters as the date text, and do not skip the record. This keeps the skip rules limited to the source's stated rules.

## Purpose

`--since` and `--until` keep records whose start date lies in an inclusive range. The start date is the first 10 characters of `started_at`. The CLI validates the option values before this filter runs.

## Behavior

- Start date = first `min(10, len(started_at))` characters of `started_at`.
- With `--since D`, keep records whose start date is greater than or equal to `D`.
- With `--until D`, keep records whose start date is less than or equal to `D`.
- Comparison is byte-wise on `YYYY-MM-DD` text, which orders the same as calendar dates.
- Options that are not given do not constrain the range.

## Programmatic Acceptance

=== AC filter-date-inclusive-range ===
Intent: Records on the since and until boundaries are kept; records outside the range are dropped.
Requires: executable=python3; scope=test

def start_date(started_at):
    return started_at[:10]

def keep(record, since, until):
    d = start_date(record["started_at"])
    if since is not None and d < since:
        return False
    if until is not None and d > until:
        return False
    return True

records = [
    {"started_at": "2026-10-13T23:59:59.000Z"},
    {"started_at": "2026-10-14T00:00:00.000Z"},
    {"started_at": "2026-10-15T12:00:00.000Z"},
    {"started_at": "2026-10-16T00:00:00.000Z"},
    {"started_at": "2026-10-17T00:00:00.000Z"},
]
kept = [r["started_at"] for r in records if keep(r, "2026-10-14", "2026-10-16")]
assert kept == [
    "2026-10-14T00:00:00.000Z",
    "2026-10-15T12:00:00.000Z",
    "2026-10-16T00:00:00.000Z",
]
=== END AC filter-date-inclusive-range ===

# FEATURE: Report Formatting

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Provide the shared minutes formatter, the cost formatter, and the CSV writer used by every report. |
| Depends On  | ARCHITECTURE.md |
| Provides    | FormatMinutes, FormatCost, WriteCSV |
| Consumes    | none |

## Questions

- None.

## Purpose

Every report shares three output rules: minutes are written in tenths of a minute, cost is written with four decimal places, and rows are written as CSV with `\n` line endings. Centralising these keeps every report byte-consistent.

## Behavior

- `FormatMinutes(ms int64) string`: `t = (ms + 3000) / 6000` in integer division, written as `t/10`, a period, and `t%10`. For example `95000` ms writes `1.6`.
- `FormatCost(usd float64) string`: `fmt.Sprintf("%.4f", usd)`.
- `WriteCSV(w io.Writer, rows [][]string) error`: writes each row with `encoding/csv`, comma-separated, `\n` line endings.

## Programmatic Acceptance
