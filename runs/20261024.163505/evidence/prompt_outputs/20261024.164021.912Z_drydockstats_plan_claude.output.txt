# Feature: Models Report

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Produce the per-provider and per-model CSV report over the filtered log records. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogModel.md, FEATURE-LogNumbers.md, FEATURE-LogFailed.md, FEATURE-FilterTarget.md, FEATURE-FilterDate.md, FEATURE-FormatCSV.md, FEATURE-FormatCost.md |
| Provides    | models report |
| Consumes    | model attribution, record aggregates, CSV and format helpers |

## Questions

- None.

## Purpose

Write one CSV row per provider and model pair over the records that pass the active `--target`, `--since`, and `--until` filters. Each row reports calls, failed calls, summed input, cached, and output tokens, and summed cost. The model of a record comes from `result.stats.model` when present and non-empty, otherwise `job.model`, and the provider comes from `job.llm`.

## Output

Header row, in this exact order:

```
provider,model,calls,failed,input_tokens,cached_tokens,output_tokens,cost_usd
```

- One data row per distinct `(provider, model)` pair, ordered by provider ascending, then model ascending, by byte value.
- `calls` counts filtered records in the pair; `failed` counts those with a status other than `succeeded`.
- Token columns are integer sums; absent or null values count as zero.
- `cost_usd` is the summed cost written with `%.4f`.
- A final `TOTAL` row over all filtered records leaves the provider and model cells empty: `TOTAL,,…`.
- A report with no matching records writes the header and a `TOTAL,,0,0,0,0,0,0.0000` row.

## Acceptance Source

- `sources/run.sh` A4, B5, and C1-style zero-match behavior for this report.
- `sources/INSTRUCTIONS.md` Output table row `models`.

## Programmatic Acceptance

# Feature: Daily Report

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Produce the per-start-date CSV report over the filtered log records. |
| Depends On  | ARCHITECTURE.md, FEATURE-FilterTarget.md, FEATURE-FilterDate.md, FEATURE-LogNumbers.md, FEATURE-LogFailed.md, FEATURE-FormatCSV.md, FEATURE-FormatMinutes.md |
| Provides    | daily report |
| Consumes    | record aggregates, CSV and format helpers |

## Questions

- None.

## Purpose

Write one CSV row per start date over the records that pass the active `--target`, `--since`, and `--until` filters. A record's start date is the first 10 characters of `started_at`. Tokens per row are input plus cached plus output.

## Output

Header row, in this exact order:

```
date,calls,failed,tokens,minutes
```

- One data row per distinct start date, ordered ascending by byte value of the `YYYY-MM-DD` string.
- `tokens` is input plus cached plus output tokens summed over the date's records.
- `minutes` is the summed `elapsed_ms` formatted by the minutes rule (tenths of a minute).
- A final `TOTAL` row over all filtered records.
- A report with no matching records writes the header and a `TOTAL,0,0,0,0.0` row.

# Feature: Failures Report

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Produce the failed-record CSV report over the filtered log records. |
| Depends On  | ARCHITECTURE.md, FEATURE-FilterTarget.md, FEATURE-FilterDate.md, FEATURE-LogFailed.md, FEATURE-LogModel.md, FEATURE-FormatCSV.md |
| Provides    | failures report |
| Consumes    | failed-record accessors, model attribution, CSV helpers |

## Questions

- None.

## Purpose

Write one CSV row per failed record over the records that pass the active `--target`, `--since`, and `--until` filters. A record is failed when its `status` is any value other than `succeeded`.

## Output

Header row, in this exact order:

```
started_at,target,command,model,returncode,timed_out
```

- One data row per failed record, ordered by `started_at` then `execution_id`, ascending by byte value.
- `model` follows the model attribution rule: `result.stats.model` when present and non-empty, otherwise `job.model`.
- `returncode` is empty when `result.returncode` is null or absent; otherwise the integer.
- `timed_out` is `true` or `false`.
- No TOTAL row.
- A report with no matching failed records writes the header only.

# Feature: Report Pipeline

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Assemble the end-to-end ddkstat run from arguments to one written report. |
| Depends On  | ARCHITECTURE.md, FEATURE-ReadErrors.md, FEATURE-UsageErrors.md, FEATURE-FilterValidate.md, FEATURE-SummaryReport.md, FEATURE-CommandsReport.md, FEATURE-TargetsReport.md, FEATURE-ModelsReport.md, FEATURE-DailyReport.md, FEATURE-FailuresReport.md |
| Provides    | ddkstat <report> [options] <log> end-to-end |
| Consumes    | argument parser, reader, parser, filters, six reports, usage and read-failure paths |

## Questions

- None.

## Purpose

Assembly feature. A single run parses arguments, reads the log, skips invalid lines, applies the active filters, aggregates, and writes exactly one selected report to standard output. Diagnostics go to standard error. Exit codes follow the contract in `sources/INSTRUCTIONS.md`: `0` for success, `1` for an unreadable log, `2` for a usage error.

## Programmatic Acceptance

=== AC pipeline-each-report-exits-zero ===
Intent: Every one of the six reports runs end to end over the sample and exits 0 with non-empty stdout.
Suite: scoped
Requires: executable=python3; scope=test

import os

from drydock_go import cli_runner

sample = os.path.join("sources", "llm_sample.jsonl")
for report in ["summary", "commands", "targets", "models", "daily", "failures"]:
    code, out, err = cli_runner(report, sample)
    print(report, code, err)
    assert code == 0, (report, code, out, err)
    assert out.strip() != "", report
=== END AC pipeline-each-report-exits-zero ===

=== AC pipeline-usage-error-writes-nothing ===

Requires: executable=python3; scope=test
