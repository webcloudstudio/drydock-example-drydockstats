```text
<requirement name="build-go-module" stories="foundation">
Implement in Go 1.22 or newer using only the standard library. The application root is a Go module, and its executable is the main package at `./cmd/ddkstat`.
</requirement>
<requirement name="dispatch-report" stories="cli-entry,report-pipeline">
`<report>` is one of `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
</requirement>
<requirement name="parse-arguments" stories="cli-parse">
`<report>` comes first, options follow it, and the log path is last. Exactly one log path is required.
</requirement>
<requirement name="reject-usage-errors" stories="cli-usage">
Usage error: unknown report or option, missing option value, invalid date, missing or extra log path.
</requirement>
<requirement name="failing-command-output" stories="cli-usage,cli-read-fail">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="report-read-failure" stories="cli-read-fail">
Operational failure: the log cannot be opened or read.
</requirement>
<requirement name="read-log-records" stories="log-read">
The log is JSON Lines in UTF-8: one JSON object per line.
</requirement>
<requirement name="validate-date-options" stories="filter-validate">
A date option must be a real calendar date written `YYYY-MM-DD`.
</requirement>
<requirement name="filter-by-target" stories="filter-target">
Keep only records whose `job.target` equals `<name>` exactly.
</requirement>
<requirement name="filter-by-date-range" stories="filter-date">
Keep only records whose start date is on or after `<date>`. Keep only records whose start date is on or before `<date>`.
</requirement>
<requirement name="filters-apply-to-reports" stories="report-pipeline">
Filters apply to every report.
</requirement>
<requirement name="skip-invalid-lines" stories="log-skip">
A line is skipped when it is not a JSON object, when any of `execution_id`, `started_at`, `status`, `job.command_name`, or `job.target` is absent or not a non-empty string, or when its `execution_id` already appeared on an earlier line. Each skipped line writes one warning to standard error naming its line number.
</requirement>
<requirement name="count-skipped-lines" stories="summary-skipped">
The `skipped` count in `summary` counts skipped lines in the whole file regardless of filters.
</requirement>
<requirement name="zero-missing-numbers" stories="log-numbers">
An absent or `null` token count, cost, or duration counts as zero.
</requirement>
<requirement name="attribute-model" stories="log-model">
A record's model is `result.stats.model` when present and non-empty, otherwise `job.model`.
</requirement>
<requirement name="classify-failed-records" stories="log-failed">
A record is failed when `status` is not `succeeded`.
</requirement>
<requirement name="format-minutes" stories="fmt-minutes">
A minutes column is the group's summed `elapsed_ms` written in tenths of a minute.
</requirement>
<requirement name="format-cost" stories="fmt-cost">
A cost column is the group's summed `cost_usd` written with exactly four decimal places, as Go's `%.4f` writes a `float64`.
</requirement>
<requirement name="write-csv" stories="fmt-csv">
Every report writes CSV to standard output: one header row, then data rows, comma-separated, `\n` line endings.
</requirement>
<requirement name="total-rows" stories="fmt-csv">
Every report except `summary` and `failures` ends with a `TOTAL` row over all filtered records.
</requirement>
<requirement name="order-text-by-bytes" stories="commands-report,targets-report,models-report,daily-report,failures-report">
Text is compared by byte value.
</requirement>
<requirement name="produce-summary" stories="summary-report">
One row. `first` and `last` are the earliest and latest start dates, empty when no record matches.
</requirement>
<requirement name="produce-commands" stories="commands-report">
One per command, by calls descending, then command ascending. Then `TOTAL,…`.
</requirement>
<requirement name="produce-targets" stories="targets-report">
One per Target, by Target ascending. Then `TOTAL,…`.
</requirement>
<requirement name="produce-models" stories="models-report">
One per provider and model pair, by provider then model ascending. Then `TOTAL,,…`.
</requirement>
<requirement name="produce-daily" stories="daily-report">
One per start date, ascending. `tokens` is input plus cached plus output. Then `TOTAL,…`.
</requirement>
<requirement name="produce-failures" stories="failures-report">
One per failed record, by `started_at` then `execution_id` ascending.
</requirement>
<requirement name="provide-test-script" stories="bld-test-script">
The completed application provides a POSIX-compatible `bin/test.sh` that runs `go vet ./...` and `go test ./...` from the application root and exits zero only when both pass.
</requirement>
<requirement name="pass-grader" stories="bld-terminal">
`drydock uat` runs `sh sources/run.sh` from the completed application root and takes its exit code and output as the score.
</requirement>
```
