Blueprint Analysis: DrydockStats

Commander Expectations

  • assert the product reads Drydock's LLM execution log (logs/llm.jsonl) and writes six CSV reports
  • assert the product runs with the Go standard library only and no database
  • assert malformed, non-object, incomplete, and duplicate log lines are skipped without failing the run
  • assert every report matches the supplied known answers in sources/run.sh byte for byte
  • assert the Target and date filters narrow every report
  • assert the reporter is invoked as ddkstat <report> [options] <log>

Planning Instructions

Delivery Shape

The system is a single Go command-line executable. Input: one JSON Lines file path plus optional --target, --since, and --until filters. Output: one CSV report to standard output, with diagnostics on standard error. Required execution flow: parse arguments, open and read the log, skip invalid lines, apply filters, aggregate, and write one of six reports.

Story Realization Map

  • LOG-001 to LOG-005: sources/INSTRUCTIONS.md Rules 1–5 and the Log section; exercised by sources/llm_sample.jsonl.
  • FLT-001 to FLT-003: sources/INSTRUCTIONS.md Command and Rule 6; date validation per Exit codes section.
  • CLI-001 to CLI-003: sources/INSTRUCTIONS.md Command and Exit codes table.
  • SUM-001 to SUM-002: sources/INSTRUCTIONS.md Output table row summary; sources/run.sh A1, B1, C2.
  • CMD-001: Output table row commands; sources/run.sh A2, B2, C1.
  • TGT-001: Output table row targets; sources/run.sh A3.
  • MDL-001: Output table row models; sources/run.sh A4, B5.
  • DLY-001: Output table row daily; sources/run.sh A5, B3.
  • FAL-001: Output table row failures; sources/run.sh A6, B4.
  • FMT-001 to FMT-003: Rules 7–9 and Output section.
  • BLD-001 to BLD-003: Stack section, Tests section, and sources/run.sh build step.

Test and Acceptance Strategy

Focused story tests cover each report, filter, skip rule, and exit code using logs written by the tests (bin/test.sh). Final verification is the single terminal story BLD-003, which runs the unfiltered grader sh sources/run.sh. That story declares Suite: full. Other stories run only their owned slice and declare Suite: scoped.

Sequencing and Dependencies

Build BLD-001 first. LOG-001 and LOG-002 precede every report and filter story. LOG-003 through LOG-005 and FLT-* precede report stories. FMT-* precede the report stories that use them. BLD-002 follows all implementation stories. BLD-003 is terminal and depends on every implementation story.

Source Conflicts and Gaps

None found. The instructions and the grader agree on every output header, ordering rule, and known answer. The grader's check U1 (no arguments) and U6 (two log paths) are consistent with the Command section's requirement of exactly one log path.
