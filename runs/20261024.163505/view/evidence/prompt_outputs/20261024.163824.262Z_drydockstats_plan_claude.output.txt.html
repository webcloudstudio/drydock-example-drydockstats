# Feature: Log Read

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Reads a JSON Lines execution log from a file path as UTF-8, one line at a time, ignoring blank lines. |
| Depends On  | ARCHITECTURE.md |
| Provides    | logfile line reader for a file path |
| Consumes    | - |

## Questions

- Q-005 (low, system_choice `skip-line`): a line whose bytes are not valid UTF-8 cannot parse as a JSON object, so it is skipped under the malformed-line rule rather than failing the run. Only an open or read failure of the file is operational (exit 1). Recorded in DECISIONS.json.

## Purpose

Provide the single entry point through which every report reads Drydock's LLM execution log. The reader yields each non-blank line as raw bytes in file order. Parsing, skipping, and aggregation happen downstream.

## Behavior

- The file path is opened and read as UTF-8 bytes, one line at a time.
- Lines that are empty or contain only whitespace are ignored and are not counted as skipped.
- Each non-blank line is passed on as raw bytes, with its one-based line number preserved for diagnostics.
- A file that cannot be opened or read returns an operational error to the caller, which maps it to exit 1.
- The reader never writes to the log file.

# Feature: Log Skip

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parses each non-blank log line as a JSON object, skips malformed, incomplete, and duplicate records with a stderr warning, and exposes the whole-file skipped count. |
| Depends On  | FEATURE-LogRead.md |
| Provides    | record parser with whole-file skipped count |
| Consumes    | logfile line reader |

## Questions

- Q-004 (material, system_choice `kept-only`): only kept records register an execution_id; a line skipped for a missing field does not block a later valid line with the same id. The sample passes under either reading. Recorded in DECISIONS.json.

## Purpose

Turn raw log lines into kept records and a whole-file skipped count. Malformed and duplicate lines are never fatal; they are skipped, counted, and reported on stderr.

## Behavior

- Each non-blank line is parsed as a JSON object. A line that is not a JSON object is skipped.
- A line is skipped when any of `execution_id`, `started_at`, `status`, `job.command_name`, or `job.target` is absent or not a non-empty string.
- A line whose `execution_id` already appeared on an earlier kept record is skipped. The first occurrence is kept.
- Each skipped line writes exactly one warning to standard error naming its one-based line number. Nothing is written to standard output.
- Skipping never changes the exit code.
- The skipped count covers the whole file and is independent of any filter.

## Programmatic Acceptance

# Feature: Log Model

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Attributes each kept record to its executed model when present and non-empty, otherwise to its requested model. |
| Depends On  | FEATURE-LogSkip.md |

## Questions

- None.

## Purpose

Name the model that ran each call, so the models and failures reports can group and display it.

## Behavior

# Feature: Log Numbers

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Treats absent or null token counts, cost, and elapsed time as zero, and keeps a record without result.stats as a record. |
| Depends On  | FEATURE-LogSkip.md |
| Provides    | Record token, cost, and elapsed accessors defaulting to zero |
| Consumes    | record parser |

## Questions

- None.

## Purpose

Let every aggregate sum numeric stats safely, so that partial or absent statistics never fail a run or drop a record.

## Behavior

- `input_tokens`, `cached_input_tokens`, `output_tokens`, `cost_usd`, and `elapsed_ms` each default to zero when absent or `null`.
- A record with no `result.stats` object is still a kept record and contributes zero to every numeric aggregate.
- Accessors return these values to the aggregation code; no numeric field causes a skip.

## Programmatic Acceptance

# Feature: Log Failed

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Classifies a kept record as failed when its status is any value other than succeeded, and exposes the fields the failures report needs. |
| Depends On  | FEATURE-LogSkip.md |
| Provides    | Record.Failed, nullable returncode, timed_out |
| Consumes    | record parser |

## Questions

- None.

## Purpose

Identify failed calls for the summary, command, target, model, daily, and failures reports.

## Behavior

- A record is failed when `status` is any value other than `succeeded`.
- The record exposes `started_at`, `job.target`, `job.command_name`, its model (per FEATURE-LogModel), `result.returncode` as nullable, and `result.timed_out` for the failures report.
- `returncode` is absent or `null` when the record has no return code; `timed_out` is treated as false when absent.
