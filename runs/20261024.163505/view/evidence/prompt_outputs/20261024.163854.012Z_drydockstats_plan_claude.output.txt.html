# FEATURE: Filter Records by Target

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Keep only log records whose job.target equals the --target value exactly. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogSkip.md, FEATURE-CommandParse.md |
| Provides    | target filter predicate |
| Consumes    | record parser, parsed options |

## Questions

- None.

## Purpose

Every report applies the same target predicate. When `--target <name>` is given, only records whose
`job.target` string equals `<name>` byte for byte are kept. Without the option, every kept record
passes.

## Behavior

- The predicate is `record.Target == targetOption` using exact byte comparison. No trimming, case
  folding, or Unicode normalization.
- When `--target` is absent, the predicate accepts every record.
- The predicate is exposed as a function value that every report aggregation applies before
  aggregating. It is never applied by individual reports on their own.
- The `skipped` count is not affected by this predicate; it is computed by the parser over the whole
  file (see FEATURE-SkippedCount.md).
- `--target` with an empty string value matches only records whose target is the empty string. Such
  records cannot exist because `job.target` must be a non-empty string, so the result is zero matches
  and exit 0.

## Programmatic Acceptance

Intent: A record whose job.target equals the --target value is kept and a record differing only in case or trailing space is not.

# FEATURE: Filter Records by Start Date

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Keep only log records whose start date falls within the inclusive --since and --until range. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogSkip.md, FEATURE-CommandParse.md, FEATURE-FilterValidate.md |
| Provides    | date range filter predicate |
| Consumes    | record parser, parsed options |

## Questions

- None.

## Purpose

Every report applies the same start-date predicate. A record's start date is the first 10 characters
of its `started_at` string. When `--since` or `--until` is given, only records whose start date lies
within the inclusive range are kept.

## Behavior

- Start date = `started_at[0:10]`, compared as a `YYYY-MM-DD` string. Byte-order comparison of
  validated dates equals chronological order.
- `--since D` keeps records with start date `>= D`. `--until D` keeps records with start date `<= D`.
  Both bounds are inclusive and independently optional.
- Inverted ranges (`--since` later than `--until`) match no record and exit 0; the report is
  header-only or zero-TOTAL. This is the narrowest consistent behavior under the AC-004 precedent.
- Option values are validated as real calendar dates by FEATURE-FilterValidate.md before this
  predicate is built; this feature receives only valid dates.
- The `skipped` count is not affected by this predicate.

## Programmatic Acceptance

=== AC filter-date-inclusive-bounds ===

Requires: executable=python3; scope=test

# FEATURE: Validate Date Option Values

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Accept --since and --until only as real calendar dates written YYYY-MM-DD; any other value is a usage error with exit 2. |
| Depends On  | ARCHITECTURE.md, FEATURE-UsageErrors.md |
| Provides    | validated --since and --until values |
| Consumes    | usage-error path |

## Questions

- None.

## Purpose

The date options feed the date filter. Only real calendar dates reach it, so an impossible date such
as `2026-13-01` or `2026-02-30` cannot silently filter the log. Validation runs over the full argument
list, including an invalid date that appears after the log path.

## Behavior

- A date value must match the form `YYYY-MM-DD` exactly: four digits, a hyphen, two digits, a hyphen,
  two digits.
- The value must name a real calendar date. Month is 01 through 12. Day must be valid for that month
  and year, including leap years in the Gregorian calendar.
- Any other value is a usage error: exit 2, nothing on stdout, one diagnostic line on stderr.
- Validation applies to every `--since` and `--until` occurrence, even when the log path precedes it.

## Programmatic Acceptance

# FEATURE: Format Minutes in Tenths

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Render a summed elapsed_ms as minutes to one decimal place using the specified integer rounding. |
| Depends On  | ARCHITECTURE.md |
| Provides    | FormatMinutes(ms) string |
| Consumes    | none |

## Questions

- None.

## Purpose

Every minutes column in every report is rendered by this single formatter so the rounding rule is
defined in one place.

## Behavior

- Input: the summed `elapsed_ms` of a group, as a non-negative integer.
- Compute `t = (ms + 3000) / 6000` in integer division.
- Output is `t / 10`, a period, then `t % 10`. Example: 95000 ms gives `t = 16`, rendered `1.6`.
- Zero input gives `t = 0`, rendered `0.0`.

## Programmatic Acceptance
