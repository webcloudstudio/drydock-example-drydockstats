# Architecture: DrydockStats

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | A Go 1.22+ standard-library command-line reporter that reads Drydock's JSON Lines LLM execution log and writes six CSV reports. |
| Depends On  | — |
| Provides    | go.mod module drydock.local/ddkstat, bin/test.sh launcher, cmd/ddkstat main package |
| Consumes    | — |

## Questions

- None.

## Compass

Build a single-binary Go CLI. Inputs: one JSON Lines log path. Outputs: CSV on standard output, diagnostics on standard error. Exit 0 on success including skipped lines, 1 on unreadable log, 2 on usage error.

## Technology Stack

- Go 1.22 or newer, standard library only. Executable at `./cmd/ddkstat`. Governed by `go.md`.
- `go test` and `go vet` run through `bin/test.sh`. Governed by `go.md`.
- JSON Lines read with `encoding/json`, one object per line. No Rigging file.
- POSIX `sh` for `bin/test.sh` and the supplied grader. Governed by `common.md`.
- No CLI platform file is selected; the CLI follows `go.md`'s native layout (`cmd/ddkstat` main calls `internal/cli` `Run(args, stdout, stderr) int`).
- No database. The log is file input, not persistent state.

## Modules

The application root is the Go module `drydock.local/ddkstat`, declared in `go.mod` with a `go 1.22` directive and no `require` directives.

| Module | Owns | Permitted access |
|--------|------|------------------|
| `cmd/ddkstat` | Process startup only; calls `os.Exit` with the result of `internal/cli` `Run`. | `internal/cli` |
| `internal/cli` | Argument parsing, report dispatch, usage-error and read-error mapping to exit codes. | `internal/log`, `internal/report`, standard library |
| `internal/log` | JSON Lines ingestion, line classification, skip rule, model attribution, numeric zero-fill, failed flag. | Standard library |
| `internal/report` | Aggregation and formatting for the six reports; minutes and cost formatting; CSV writing. | `internal/log`, standard library |
| `internal/doc` | Placeholder package so `go vet ./...` and `go test ./...` always have a package to match. | None |

## Boundaries

- The log file is read-only. No module writes to it.
- Parsing, aggregation, and formatting are separate functions and are unit-tested separately.
- Diagnostics go to standard error. Standard error is never the verdict of any check.
- Application code never reads `sources/run.sh` and never embeds a report answer.

## Interfaces

- `cli.Run(args []string, stdout, stderr io.Writer) int` is the single entry point; the process exit status is its return value.
- `log.ReadLines` yields non-blank lines with 1-based line numbers from an `io.Reader`; a thin file-open wrapper calls it.
- `log.Normalize` yields kept records and the whole-file skipped count.

## Technical Decisions

- Standard library only; no third-party modules.
- Filters are applied after skipping, so the `skipped` count in `summary` is unaffected by filters.
- Dates are validated with `time.Parse` layout `2006-01-02`, rejecting any string that does not round-trip exactly.
- Cost is held as `float64`; durations are held as integer milliseconds and rounded only in the formatter.

- None.

## Guardrails

- The application must not add any third-party module to `go.mod`.
- No module may write to the log file being read.
- Application code must not read `sources/run.sh`.
