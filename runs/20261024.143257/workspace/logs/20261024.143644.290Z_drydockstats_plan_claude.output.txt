# FEATURE: CLI Target Filter

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Keep only records whose job.target equals the --target value exactly, before every report is aggregated. |
| Depends On  | FEATURE-CliParse.md, FEATURE-LogSkip.md |
| Provides    | --target <name> filter applied before every report |
| Consumes    | Normalized records from FEATURE-LogSkip.md; option grammar from FEATURE-CliParse.md |

## Questions

- None.

## Purpose

The operator narrows every report to one Target. The filter reads the Target name exactly as the log
records it, so `Alpha` and `alpha` are different Targets.

## Behavior

- The filter runs after lines are skipped and before aggregation.
- Equality is exact and case-sensitive on `job.target`.
- The filter applies to every report: `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
- The `skipped` count in `summary` counts the whole file and is never filtered.
- A `--target` value that matches nothing produces the empty-match output defined by the report
  features; it is not a usage error.

## Programmatic Acceptance

=== AC cli-target-exact ===
Intent: --target keeps only records whose job.target equals the value exactly, case-sensitively.

import csv
import io
import json
import os
import sys
import tempfile

from drydock_go import cli_runner

keep = "Alpha"
targets = ["Alpha", "Alpha", "Alpha", "alpha", "alpha", "Alphabet", "Beta"]
expected = sum(1 for target in targets if target == keep)

directory = tempfile.mkdtemp()
path = os.path.join(directory, "llm.jsonl")
with open(path, "w", encoding="utf-8") as handle:
    for index, target in enumerate(targets):
        record = {
            "schema_version": 1,
            "execution_id": f"exec-{index}",
            "started_at": "2026-10-14T06:00:00.000Z",
            "status": "succeeded",
            "job": {"command_name": "build", "target": target, "llm": "claude", "model": "haiku"},
            "result": {"returncode": 0, "timed_out": False},
        }
        handle.write(json.dumps(record) + "\n")

code, out, err = cli_runner("summary", "--target", keep, path)
print(err, file=sys.stderr)
assert code == 0, (code, out, err)
rows = list(csv.DictReader(io.StringIO(out)))
assert len(rows) == 1, out
assert int(rows[0]["records"]) == expected, (rows[0], expected)
=== END AC cli-target-exact ===

# FEATURE: CLI Date Filters

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Keep records whose start date falls inclusively within --since and --until, using the first 10 characters of started_at. |
| Depends On  | FEATURE-CliParse.md, FEATURE-LogSkip.md |
| Provides    | --since <YYYY-MM-DD> and --until <YYYY-MM-DD> date filter applied before every report |
| Consumes    | Normalized records from FEATURE-LogSkip.md; option grammar from FEATURE-CliParse.md |

## Questions

- None.

## Purpose

The operator restricts every report to a span of start dates. Bounds are calendar dates, and a record
on a bound date is kept.

## Behavior

- The start date is the first 10 characters of `started_at`.
- `--since` keeps records whose start date is on or after the value. `--until` keeps records whose start
  date is on or before the value. Both bounds are inclusive.
- Comparison is a string comparison of `YYYY-MM-DD` values, which orders them correctly.
- The date values are validated by FEATURE-CliUsageErrors.md before this filter runs.
- The filter applies to every report. The `skipped` count is never filtered.

## Programmatic Acceptance

=== AC cli-date-range-inclusive ===
Intent: --since and --until together keep exactly the records whose start date lies on or between the bounds, inclusive.

import csv
import io
import json
import os
import sys
import tempfile

from drydock_go import cli_runner

days = ["2026-10-13", "2026-10-14", "2026-10-15", "2026-10-16", "2026-10-17"]
since = "2026-10-14"
until = "2026-10-16"
kept = [day for day in days if since <= day <= until]

directory = tempfile.mkdtemp()
path = os.path.join(directory, "llm.jsonl")
index = 0
with open(path, "w", encoding="utf-8") as handle:
    for day in days:
        for stamp in [f"{day}T00:00:00.000Z", f"{day}T23:59:59.999Z"]:
            record = {
                "schema_version": 1,
                "execution_id": f"exec-{index}",
                "started_at": stamp,
                "status": "succeeded",
                "job": {"command_name": "build", "target": "Alpha", "llm": "claude", "model": "haiku"},
                "result": {"returncode": 0, "timed_out": False},
            }
            handle.write(json.dumps(record) + "\n")
            index += 1

code, out, err = cli_runner("summary", "--since", since, "--until", until, path)
print(err, file=sys.stderr)
assert code == 0, (code, out, err)
rows = list(csv.DictReader(io.StringIO(out)))
assert len(rows) == 1, out
assert int(rows[0]["records"]) == 2 * len(kept), (rows[0], kept)
assert rows[0]["first"] == min(kept), rows[0]
assert rows[0]["last"] == max(kept), rows[0]
=== END AC cli-date-range-inclusive ===

# FEATURE: CLI Usage Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Map every usage error to exit code 2, with no standard output and exactly one standard error line. |
| Depends On  | FEATURE-CliParse.md |
| Provides    | Exit code 2 for usage errors |
| Consumes    | Argument grammar and report dispatch table from FEATURE-CliParse.md |

## Questions

- None.

## Purpose

The operator gets a single diagnostic line and exit code 2 when the command line is malformed, so
scripts can tell a mistake in the invocation from an unreadable log.

## Behavior

- Usage errors are: an unknown report name, an unknown option, an option missing its value, an invalid
  date, and a missing or extra log path, including no arguments at all.
- Each usage error exits `2`, writes nothing to standard output, and writes exactly one line to standard error.
- A date is valid only when it is a real `YYYY-MM-DD` calendar date. Validation uses `time.Parse` with the
  layout `2006-01-02` and rejects any string that does not round-trip exactly.

## Programmatic Acceptance

=== AC cli-usage-unknown-report-and-option ===
Intent: An unknown report name or unknown option exits 2 with no standard output and one standard error line.

    assert len(err.strip().splitlines()) == 1, (args, err)

# FEATURE: CLI Read Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Map a log that cannot be opened or read to exit code 1, with no standard output and exactly one standard error line. |
| Depends On  | FEATURE-CliParse.md, FEATURE-LogReader.md |
| Provides    | Exit code 1 for operational failures |
| Consumes    | Read errors returned by FEATURE-LogReader.md; argument result from FEATURE-CliParse.md |

## Questions

- None.

## Purpose

When the log itself cannot be used, the operator gets exit code 1 and a single diagnostic line, which is
distinct from a mistake in the command line.

## Behavior

- A log path that does not exist exits `1`.
- A log path that cannot be read, such as a directory, exits `1`.
- Each such failure writes nothing to standard output and exactly one line to standard error.
- A missing file is an operational failure, not a usage error. The path has already passed argument validation.
- A readable log is not affected by this mapping and exits `0`.

## Programmatic Acceptance

# FEATURE: Report Formatting

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Provide the minutes, cost, and CSV writing helpers used by every report, kept separate from aggregation. |
| Depends On  | ARCHITECTURE.md |
| Provides    | internal/report FormatMinutes, FormatCost, CSV writer |
| Consumes    | Summed elapsed_ms and cost_usd values from FEATURE-LogNumbers.md |

## Questions

- None.

## Purpose

Every report writes minutes, cost, and CSV in one agreed form. Formatting is kept apart from aggregation
so each can be unit-tested on its own.

## Behavior

- Minutes: `t = (ms + 3000) / 6000` in integer division, written as `t / 10`, a `.`, and `t % 10`.
  For example, 95000 ms is written as `1.6`.
- Cost: a float64 written with exactly four decimal places, as Go's `%.4f` writes it.
- CSV: one header row, then data rows, comma-separated, with `\n` line endings.
- The package provides unit tests named `TestFormatMinutes`, `TestFormatCost`, and `TestWriteCSV`.
  Each test covers its helper's full rule, including zero values.
