<requirement name="stack-go-module" stories="go-foundation,build-executable">
Implement in Go 1.22 or newer using only the standard library. The application root is a Go module, and its executable is the main package at `./cmd/ddkstat`. Tests run under `go test`.
</requirement>
<requirement name="read-json-lines-log" stories="log-reader">
The log is JSON Lines in UTF-8: one JSON object per line.
</requirement>
<requirement name="blank-lines-ignored" stories="log-reader">
Blank lines are ignored and not counted.
</requirement>
<requirement name="command-syntax" stories="cli-parse">
`<report>` comes first, options follow it, and the log path is last. Exactly one log path is required.
</requirement>
<requirement name="usage-errors-exit-2" stories="cli-usage-errors">
Usage error: unknown report or option, missing option value, invalid date, missing or extra log path.
</requirement>
<requirement name="unreadable-log-exit-1" stories="cli-read-errors">
Operational failure: the log cannot be opened or read.
</requirement>
<requirement name="failing-command-output" stories="cli-read-errors,cli-usage-errors">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="success-exit-0" stories="log-skip,report-empty-match">
Success, including a log with skipped lines or no matching records.
</requirement>
<requirement name="target-filter" stories="cli-target-filter">
Keep only records whose `job.target` equals `<name>` exactly.
</requirement>
<requirement name="date-filters" stories="cli-date-filters">
Keep only records whose start date is on or after `<date>`. Keep only records whose start date is on or before `<date>`. A date option must be a real calendar date written `YYYY-MM-DD`.
</requirement>
<requirement name="filters-apply-to-every-report" stories="cli-target-filter,cli-date-filters">
Filters apply to every report.
</requirement>
<requirement name="skip-malformed-and-duplicate-lines" stories="log-skip">
A line is skipped when it is not a JSON object, when any of `execution_id`, `started_at`, `status`, `job.command_name`, or `job.target` is absent or not a non-empty string, or when its `execution_id` already appeared on an earlier line. The first occurrence of an `execution_id` is kept.
</requirement>
<requirement name="skip-warning" stories="log-skip,log-reader">
Each skipped line writes one warning to standard error naming its line number. Skipping never changes the exit code.
</requirement>
<requirement name="summary-skipped-count-whole-file" stories="report-summary,log-skip">
The `skipped` count in `summary` counts skipped lines in the whole file regardless of filters.
</requirement>
<requirement name="zero-fill-missing-numbers" stories="log-numbers">
An absent or `null` token count, cost, or duration counts as zero. A record with no `result.stats` object at all is still a record.
</requirement>
<requirement name="failed-status" stories="log-numbers">
A record is failed when `status` is not `succeeded`.
</requirement>
<requirement name="model-attribution" stories="log-model">
A record's model is `result.stats.model` when present and non-empty, otherwise `job.model`.
</requirement>
<requirement name="minutes-column" stories="report-format">
A minutes column is the group's summed `elapsed_ms` written in tenths of a minute: `t = (ms + 3000) / 6000` in integer division, written as `t / 10`, a `.`, and `t % 10`. `95000` ms is `1.6`.
</requirement>
<requirement name="cost-column" stories="report-format">
A cost column is the group's summed `cost_usd` written with exactly four decimal places, as Go's `%.4f` writes a `float64`.
</requirement>
<requirement name="csv-output" stories="report-format,report-summary,report-commands,report-targets,report-models,report-daily,report-failures">
Every report writes CSV to standard output: one header row, then data rows, comma-separated, `\n` line endings.
</requirement>
<requirement name="total-row" stories="report-commands,report-targets,report-models,report-daily">
Every report except `summary` and `failures` ends with a `TOTAL` row over all filtered records.
</requirement>
<requirement name="byte-order-text" stories="report-commands,report-targets,report-models,report-daily,report-failures">
Text is compared by byte value.
</requirement>
<requirement name="summary-report" stories="report-summary">
`first` and `last` are the earliest and latest start dates, empty when no record matches.
</requirement>
<requirement name="commands-report" stories="report-commands">
One per command, by calls descending, then command ascending. Then `TOTAL,…`.
</requirement>
<requirement name="targets-report" stories="report-targets">
One per Target, by Target ascending. Then `TOTAL,…`.
</requirement>
<requirement name="models-report" stories="report-models">
One per provider and model pair, by provider then model ascending. Then `TOTAL,,…`.
</requirement>
<requirement name="daily-report" stories="report-daily">
One per start date, ascending. `tokens` is input plus cached plus output.
</requirement>
<requirement name="failures-report" stories="report-failures">
One per failed record, by `started_at` then `execution_id` ascending. `returncode` is empty when `null` or absent. `timed_out` is `true` or `false`.
</requirement>
<requirement name="empty-match-output" stories="report-empty-match">
When no record matches, a report writes its header and, where it has one, a `TOTAL` row of zeros (`0.0` minutes, `0.0000` cost).
</requirement>
<requirement name="test-launcher" stories="go-foundation,test-suite">
The completed application provides a POSIX-compatible `bin/test.sh` that runs `go vet ./...` and `go test ./...` from the application root and exits zero only when both pass.
</requirement>
<requirement name="test-coverage" stories="test-suite">
The suite covers each report, each filter, each skip rule, and each exit code using logs written by the tests.
</requirement>
<requirement name="harness-build-and-checks" stories="build-executable,grader-run">
The harness runs `go build -o <temporary path> ./cmd/ddkstat` and then runs 20 checks against `sources/llm_sample.jsonl`.
</requirement>
<requirement name="grader-score" stories="grader-run">
`drydock uat` runs `sh sources/run.sh` from the completed application root and takes its exit code and output as the score.
</requirement>
