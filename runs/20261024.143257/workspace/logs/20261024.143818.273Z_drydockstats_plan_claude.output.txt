# FEATURE: CLI Target Filter

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Restrict every report to records whose job.target equals the --target value exactly. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliParse.md, FEATURE-LogSkip.md |
| Provides    | --target filter applied before every report |
| Consumes    | Record.Target, internal/log Normalize |

## Questions

- None.

## Purpose

`--target <name>` keeps only the normalized records whose `job.target` equals `<name>` byte for
byte. The comparison is case-sensitive and is not trimmed. The filter runs after skipping and
before aggregation, so every report reads the same filtered set. The `skipped` count in `summary`
is computed before this filter and is never reduced by it.

## Behavior

- A record is kept when its target equals the option value exactly.
- An option value that matches no record yields an empty filtered set, not an error.
- The filter composes with `--since` and `--until` as a logical AND.
- Absent the option, every normalized record is kept.

# FEATURE: CLI Date Filters

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Keep records whose start date falls inclusively within --since and --until. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliParse.md, FEATURE-LogSkip.md |
| Provides    | --since and --until filters over the start date |
| Consumes    | Record.StartedAt, internal/log Normalize |

## Questions

- None.

## Purpose

The start date of a record is the first 10 characters of `started_at`. `--since` keeps records
whose start date is on or after the value. `--until` keeps records whose start date is on or
before the value. Both bounds are inclusive. Dates are compared as strings, which orders
`YYYY-MM-DD` correctly. Date validity is checked by `FEATURE-CliUsageErrors.md`, not here.

## Behavior

- With `--since` only, records with start date `>= since` are kept.
- With `--until` only, records with start date `<= until` are kept.
- With both, the two bounds apply together as a logical AND.
- A bound later than every record yields an empty filtered set, not an error.

## Programmatic Acceptance

=== AC date-filter-since-inclusive ===
Intent: --since keeps records starting on the given date and later, and drops earlier ones.
Suite: scoped

# FEATURE: CLI Usage Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Map every usage error to exit code 2 with no stdout and exactly one stderr line. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliParse.md |
| Provides    | Exit code 2 for usage errors |
| Consumes    | cli.Run argument handling |

## Questions

- None.

## Purpose

A usage error is an unknown report name, an unknown option, a missing option value, a date that is
not a real `YYYY-MM-DD` calendar date, or a missing or extra log path. Each exits `2`, writes
nothing to stdout, and writes exactly one diagnostic line to stderr. Dates are validated with
`time.Parse` using layout `2006-01-02`, rejecting any string that does not round-trip exactly.

## Behavior

- Unknown report, unknown option, missing option value, invalid date, and missing or extra log path
  each return exit code `2`.
- stdout is empty for every usage error.
- stderr contains exactly one line.

## Programmatic Acceptance

# FEATURE: Report Format

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Provide the minutes, cost, and CSV writing helpers used by every report. |
| Depends On  | ARCHITECTURE.md, FEATURE-Executable.md |
| Provides    | internal/report FormatMinutes, FormatCost, CSV writer |
| Consumes    | Record numeric fields |

## Questions

- None.

## Purpose

Shared formatting used by every report. Minutes are derived from summed `elapsed_ms` as
`t = (ms + 3000) / 6000` in integer division, rendered as `t/10`, a dot, and `t%10`. Cost is
rendered with `%.4f`. The CSV writer emits one header row and `\n` line endings. Formatting stays
separate from aggregation so each is unit-tested on its own.

## Behavior

- `FormatMinutes(95000)` renders `1.6`.
- `FormatMinutes(0)` renders `0.0`.
- `FormatCost` renders a `float64` with exactly four decimal places.
- The CSV writer writes a header row followed by data rows, comma-separated, with `\n` endings.

## Programmatic Acceptance
