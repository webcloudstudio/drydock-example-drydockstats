# Feature: Log Reader

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Read the log path as JSON Lines, yielding each non-blank line with its 1-based line number. |
| Depends On  | ARCHITECTURE.md |
| Provides    | internal/log ReadLines, internal/log Line |
| Consumes    | — |

## Questions

- None.

## Purpose

Turn the log file into an ordered sequence of non-blank lines, each carrying its 1-based line number, so that later stages can classify and count them.

## Behavior

- The file is read as UTF-8.
- Each non-blank line is yielded with its 1-based line number. A line is blank when it contains only whitespace.
- Blank lines are ignored and are not counted as records or as skips.
- The core reader accepts an `io.Reader` so tests can supply a `bytes.Buffer`. Opening the file is a thin wrapper around it.
- No JSON parsing or line classification happens here. Classification belongs to the skip stage.
- When the file cannot be opened or a read fails, an error is returned so the caller can map it to exit code 1.

# Feature: Log Skip

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Classify each non-blank line and skip malformed or duplicate records, warning on stderr. |
| Depends On  | FEATURE-LogReader.md |
| Provides    | internal/log Normalize, internal/log Record, skipped count |
| Consumes    | internal/log ReadLines, internal/log Line |

## Questions

- None.

## Purpose

Separate usable records from unusable lines so every report aggregates only well-formed, unique records, while counting what was dropped.

## Behavior

- A line is skipped when it is not a JSON object.
- A line is skipped when any of `execution_id`, `started_at`, `status`, `job.command_name`, or `job.target` is absent or not a non-empty string.
- A line is skipped when its `execution_id` already appeared on an earlier line. The first occurrence is kept.
- Each skipped line writes one warning to stderr naming its line number. Stdout is never written.
- The stage returns the kept records and the total skipped count for the whole file.
- Skipping never changes the exit code.
- Filters are applied after this stage, so the skipped count is unaffected by filters.

# Feature: Log Model

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Attribute each record to the executed model, falling back to the requested model. |
| Depends On  | FEATURE-LogReader.md |
| Provides    | Record.Model derivation in internal/log |
| Consumes    | internal/log Normalize, internal/log Record |

## Questions

- None.

## Purpose

Give every report one consistent model attribution per record, preferring the model that actually executed.

## Behavior

- A record's Model is `result.stats.model` when that field is present and non-empty.
- Otherwise the Model is `job.model`.
- The derivation lives inside the record normalizer, so every report reads Model from the same field.

# Feature: Log Numbers

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Zero-fill absent numeric fields and derive the failed flag on each normalized record. |
| Depends On  | FEATURE-LogReader.md |
| Provides    | Record numeric fields, Record.Failed, Record.ReturnCode, Record.TimedOut |
| Consumes    | internal/log Normalize, internal/log Record |

## Questions

- None.

## Purpose

Make every numeric field safe to sum, and make failure status explicit, so reports never special-case missing data.

## Behavior

- An absent or null `input_tokens`, `cached_input_tokens`, `output_tokens`, `cost_usd`, or `elapsed_ms` counts as zero.
- A record with no `result.stats` object is still a record, with zero tokens, cost, and duration.
- `Failed` is set when `status` is not `succeeded`.
- `ReturnCode` is kept as nil when `returncode` is null or absent, and as its integer value otherwise.
- `TimedOut` is kept from `result.timed_out`.
- Cost is kept as `float64`. Durations are kept as integer milliseconds so the formatter can apply the minutes and cost rounding rules.

# Feature: CLI Parse

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parse the report name, options, and the single log path in the required order. |
| Depends On  | ARCHITECTURE.md, FEATURE-Executable.md |
| Provides    | internal/cli Run dispatch, report name table, option grammar |
| Consumes    | internal/log ReadLines |

## Questions

- None.

## Purpose

Turn the command line into a validated report request, or a usage error, before any log is read.

## Behavior

- The first argument is the report name. Options follow it. Exactly one log path is last.
- The six report names are `summary`, `commands`, `targets`, `models`, `daily`, and `failures`.
- A local `flag.FlagSet` with `flag.ContinueOnError` parses the options. Tests use `bytes.Buffer` for output.
- `--target`, `--since`, and `--until` are declared so they parse. Their semantics belong to the filter stories.
- This stage owns the report dispatch table. Each report story registers its name here.
