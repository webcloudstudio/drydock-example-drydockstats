# ARCHITECTURE: DrydockStats

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Module layout, package boundaries, shared types, and technical decisions for the ddkstat LLM log reporter. |
| Depends On  | None |
| Provides    | go.mod, cmd/ddkstat, internal/cli, internal/logread, internal/report |

## Questions

- None.

## Purpose

`ddkstat` is a command-line reporter for Drydock's LLM execution log (`logs/llm.jsonl`). It reads a
JSON Lines file, skips malformed and duplicate lines, narrows the records by optional Target and
date filters, and writes one of six CSV reports to standard output. It has no database and no
network access, and it never writes to the log it reads.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`, which remains the decision of record.

| Technology | Where it applies |
|---|---|
| Go 1.22 or newer, standard library only | All application code; no third-party modules |
| `go test` and `go vet` | The test runner behind `bin/test.sh` |
| JSON Lines | The input format, decoded with `encoding/json` |
| POSIX sh | `bin/test.sh` and the supplied grader `sources/run.sh` |

## Module Layout

```text
go.mod                    module declaration, Go 1.22 or newer, no require lines
cmd/ddkstat/main.go       package main; the only caller of os.Exit
internal/cli/             Run, argument parsing, exit codes, usage line
internal/logread/         reading, skip rules, de-duplication, record model
internal/report/          filters, aggregation, and CSV formatting as separate functions
bin/test.sh               POSIX launcher for go vet and go test
```

## Package Boundaries

| Package | Owns | May import |
|---|---|---|
| `cmd/ddkstat` | Process start; passes `os.Args[1:]`, `os.Stdout`, `os.Stderr` to `cli.Run`; exits with its result | `internal/cli` |
| `internal/cli` | Argument parsing, date validation, exit codes, orchestration of read, filter, aggregate, format | `internal/logread`, `internal/report` |
| `internal/logread` | Opening and reading the log, line numbering, skip and duplicate rules, the `Record` model | standard library |
| `internal/report` | Filtering, aggregation per report, minutes and cost formatting, CSV writing | `internal/logread` |

Parsing the log, aggregating, and formatting are separate functions, each unit-tested. Business
logic lives in `internal/logread` and `internal/report`; `internal/cli` only wires them together.

## Shared Types and Interfaces

```go
// internal/logread
type Record struct {
    ExecutionID  string
    StartedAt    string // RFC 3339 UTC; the first 10 characters are the start date
    Status       string
    Command      string // job.command_name
    Target       string // job.target
    Provider     string // job.llm
    Model        string // result.stats.model when non-empty, otherwise job.model
    InputTokens  int64
    CachedTokens int64
    OutputTokens int64
    CostUSD      float64
    ElapsedMS    int64
    ReturnCode   *int // nil when null or absent
    TimedOut     bool
}

func (r Record) Date() string   // StartedAt[:10]
func (r Record) Failed() bool   // Status != "succeeded"

type Result struct {
    Records []Record // kept records in file order
    Skipped int      // skipped lines in the whole file
}

func Read(r io.Reader, warn io.Writer) (Result, error)
func ReadFile(path string, warn io.Writer) (Result, error)
```

```go
// internal/cli
type Options struct {
    Report string
    Target string
    HasTarget bool
    Since  string // YYYY-MM-DD or empty
    Until  string // YYYY-MM-DD or empty
    Log    string
}

func Parse(args []string) (Options, error)
func Run(args []string, stdout, stderr io.Writer) int
```

`Run` uses a local `flag.FlagSet` with `flag.ContinueOnError` or an equivalent hand parser, never
the global flag set, and is tested with `bytes.Buffer`. Report output is buffered and written to
standard output only after the log has been read successfully, so a failing command leaves
standard output empty.

## Execution Flow

parse arguments, open the log, ingest records applying the skip rules, apply the Target and date
filters, compute one report, write CSV. The `skipped` count is computed over the whole file before
any filter applies.

## Shared Output Rules

CSV with one header row and `\n` line endings; minutes written as tenths with
`t = (ms + 3000) / 6000` in integer division and formatted `t/10`, `.`, `t%10`; cost written with
`%.4f`; text ordered by byte value; a `TOTAL` row of zeros when no record matches, where the report
has one.

## Exit Codes

| Code | Meaning |
|---|---|
| 0 | Success, including skipped lines or no matching records |
| 1 | The log cannot be opened or read |
| 2 | Usage error |

Diagnostics go to standard error and are never compared.

## Persistence Ownership

| Boundary | Owner module |
|---|---|
| Persistence, configuration, file stores, external services | None; the application has no database and no external service. The log is read-only input. |

## Technical Decisions

- Records that fail any rule never register their `execution_id`, so a later valid record with that
  id is kept.
- `--help` is an unknown option and exits 2 with the usage line on standard error.
- A repeated option keeps its last occurrence.
- A directory given as the log path is an unreadable log and exits 1.
- A numeric field with a JSON type other than number or `null` counts as zero.

# FEATURE: Command Line

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Parse the ddkstat command line into a report name, the three options, and exactly one trailing log path. |
| Depends On  | ARCHITECTURE.md |
| Provides    | ddkstat <report> [--target <name>] [--since <YYYY-MM-DD>] [--until <YYYY-MM-DD>] <log> |

## Questions

- None.

## Purpose

The command is `ddkstat <report> [--target <name>] [--since <date>] [--until <date>] <log>`. The
report comes first, options follow it, and the log path is last. This feature delivers the
parser and the executable entry point at `./cmd/ddkstat`; date validation, usage-error exit codes,
and unreadable-log handling belong to their own features.

## Behavior

- `<report>` is one of `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
- The accepted options are `--target <name>`, `--since <date>`, and `--until <date>`, each taking
  one value, in any order, between the report and the log path.
- Exactly one log path is the final argument.
- A repeated option keeps its last occurrence.
- `cli.Parse(args []string) (Options, error)` returns the typed `Options` from `ARCHITECTURE.md`,
  and returns a non-nil error for any argument list it cannot accept. `cli.Run` maps that error to
  the usage-error exit code in the usage-errors feature.
- `go build ./cmd/ddkstat` produces the executable using only the standard library.

## Required Unit Tests

The build writes these tests in `internal/cli`, each against real parser output:

| Test | Behavior |
|---|---|
| `TestParseAcceptsEveryReport` | Each of the six report names parses with a log path. |
| `TestParseOptionsFollowReport` | The three options parse in any order and populate `Options`. |
| `TestParseLogPathIsLast` | The final argument becomes `Options.Log`. |
| `TestParseRepeatedOptionLastWins` | A repeated option keeps its last value. |

# FEATURE: Log Reading

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Read the Drydock JSON Lines log line by line, ignoring blank lines and numbering every line. |
| Depends On  | ARCHITECTURE.md |
| Provides    | logread.Read, logread.ReadFile |

## Questions

- None.

## Purpose

The log is JSON Lines in UTF-8, one JSON object per line. This feature delivers the line reader in
`internal/logread`: it walks the input, discards blank lines, and hands each non-blank line, with
its 1-based line number, to the record decoder that the skip-rule features extend.

## Behavior

- `logread.Read(r io.Reader, warn io.Writer) (logread.Result, error)` reads every line of `r`.
- `logread.ReadFile(path string, warn io.Writer) (logread.Result, error)` opens the file, reads it
  with `Read`, and closes it. It returns a non-nil error when the file cannot be opened or read,
  including when the path names a directory.
- A blank line, meaning empty or whitespace only, is ignored and is neither a record nor counted as
  skipped.
- Line numbers are 1-based and count blank lines, so a warning names the physical line.
- Lines longer than the default `bufio.Scanner` token limit are read in full.
- The log file is opened read-only and never written.
- Each non-blank line is decoded as one JSON object into a `logread.Record`.

## Required Unit Tests

The build writes these tests in `internal/logread`:

| Test | Behavior |
|---|---|
| `TestReadIgnoresBlankLines` | Blank lines yield no record and no skipped count. |
| `TestReadNumbersEveryLine` | The line number used for a warning counts preceding blank lines. |
| `TestReadAcceptsLongLine` | A valid record line longer than 1 MiB is read as one record. |
| `TestReadFileMissing` | `ReadFile` on a nonexistent path returns an error. |
| `TestReadFileDirectory` | `ReadFile` on a directory returns an error. |
| `TestReadNeverWritesLog` | After `ReadFile`, the log file bytes and modification time are unchanged. |

# FEATURE: Malformed Lines

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Skip lines that are not valid records, count them, and warn on standard error without failing the run. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogReading.md |
| Provides    | logread.Result.Skipped |

## Questions

- None.

## Purpose

A malformed line must never fail the run. This feature adds the record validation rules to the
reader: a line that fails any rule is skipped, counted in `Result.Skipped`, and reported with one
warning on the warning writer naming its line number. Skipping never changes the exit code.

## Behavior

A non-blank line is skipped when any of these holds:

- It is not a JSON object, including a truncated line, a JSON array, a bare scalar, and `null`.
- It is not valid UTF-8; it is treated as not a JSON object.
- Any of `execution_id`, `started_at`, `status`, `job.command_name`, or `job.target` is absent or
  not a non-empty string.
- `started_at` does not begin with a real calendar date written `YYYY-MM-DD`, for example
  `2026-13-01` or `2026-02-30`, because every report keys on the start date.

Each skipped line writes exactly one warning to the warning writer that contains its 1-based line
number. A skipped line never registers its `execution_id`, so a later valid record with that id is
kept (see `FEATURE-DuplicateIds.md`). The skipped count covers the whole file and is independent of
any filter applied later.

## Required Unit Tests

The build writes these tests in `internal/logread`:

| Test | Behavior |
|---|---|
| `TestSkipNotJSONObject` | Truncated JSON, an array, a scalar, and `null` are each skipped. |
| `TestSkipInvalidUTF8` | A line with invalid UTF-8 bytes is skipped. |
| `TestSkipMissingRequiredField` | For each of the five required fields, absent, empty, and non-string values skip the line. |
| `TestSkipBadStartedAt` | A `started_at` without a real leading `YYYY-MM-DD` date skips the line. |
| `TestSkipWarnsWithLineNumber` | One warning per skipped line names its physical line number, counting blank lines. |
| `TestSkipDoesNotAffectValidRecords` | Valid lines around skipped lines are all kept, in file order. |

# FEATURE: Duplicate Ids

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Skip any line whose execution_id already appeared on an earlier kept record, keeping the first occurrence. |
| Depends On  | ARCHITECTURE.md, FEATURE-LogReading.md, FEATURE-MalformedLines.md |
| Provides    | logread.Dedupe |

## Questions

- None.

## Purpose

Drydock may write the same execution twice. This feature makes the reader keep the first
occurrence of each `execution_id` and skip every later repeat, counting it in `Result.Skipped` and
warning on the warning writer with its line number, without failing the run.

## Behavior

- A line is skipped as a duplicate when its `execution_id` equals that of an earlier kept record.
- The first occurrence is kept, and later repeats are skipped even when their other fields differ.
- Only a record that passes every other rule registers its `execution_id`. A line skipped as
  malformed does not register its id, so a later valid record with the same id is kept.
- Each duplicate writes one warning naming its 1-based line number.
- Duplicate detection is exact string equality on `execution_id`.
- The skipped count includes duplicates and malformed lines together, over the whole file.

## Required Unit Tests

The build writes these tests in `internal/logread`:

| Test | Behavior |
|---|---|
| `TestDuplicateFirstOccurrenceKept` | Two lines with one id yield one record, the first, and one skipped. |
| `TestDuplicateKeepsFirstEvenWhenFieldsDiffer` | The kept record carries the first line's field values. |
| `TestSkippedLineDoesNotRegisterID` | A malformed line followed by a valid line with the same id keeps the valid line. |
| `TestDuplicateWarnsWithLineNumber` | Each duplicate produces one warning naming its physical line number. |
| `TestDuplicateCountedWithMalformed` | Duplicates and malformed lines are both counted in `Skipped`. |
