# FEATURE: Models Report

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | The models report groups filtered records by provider and attributed model and ends with a TOTAL row. |
| Depends On  | FEATURE-SummaryReport.md, FEATURE-ModelAttribution.md, FEATURE-DateFilter.md |
| Provides    | ddkstat models |
| Consumes    | logread.Record.Model, report.FilterTarget, report.FilterDates |

## Questions

- None.

## Purpose

`ddkstat models <log>` answers which providers and models ran the LLM calls, and what they used and cost.

## Report Contract

- Header: `provider,model,calls,failed,input_tokens,cached_tokens,output_tokens,cost_usd`.
- One row per distinct pair of `job.llm` (provider) and the record's attributed model (`result.stats.model` when non-empty, otherwise `job.model`).
- Rows are ordered by provider ascending, then model ascending, compared by byte value.
- `calls` counts filtered records in the group; `failed` counts those whose `status` is not `succeeded`.
- Token columns are sums of `input_tokens`, `cached_input_tokens`, and `output_tokens`; absent or null values count as zero.
- `cost_usd` is the summed cost written with `%.4f`; a null or absent cost counts as zero.
- The last row is `TOTAL` with an empty model cell (`TOTAL,,...`) summing every filtered record.
- With no matching record the output is the header and a `TOTAL` row of zeros, with cost `0.0000`.
- Output is CSV with `\n` line endings. `--target`, `--since`, and `--until` narrow the records before grouping.
- Aggregation and formatting are separate, unit-tested functions in `internal/report`.

## Programmatic Acceptance

=== AC models-grouping-order-total ===
Intent: The models report groups by provider and attributed model, orders by byte value, and totals every record.
Requires: executable=go; scope=test

import csv
import io
import json
import os
import tempfile
from drydock_go import cli_runner

def rec(eid, started, status, llm, jm, stats):
    result = {"returncode": 0, "timed_out": False}

        result["stats"] = stats
    return {"execution_id": eid, "started_at": started, "status": status,
            "job": {"command_name": "build", "target": "T", "llm": llm, "model": jm},
            "result": result}

recs = [
    rec("m1", "2026-10-14T01:00:00.000Z", "succeeded", "gemini", "Zed",
        {"input_tokens": 1, "cached_input_tokens": 2, "output_tokens": 3, "cost_usd": 0.25, "elapsed_ms": 10}),
    rec("m2", "2026-10-14T02:00:00.000Z", "succeeded", "claude", "sonnet",
        {"model": "claude-sonnet-5-5", "input_tokens": 10, "cached_input_tokens": 20, "output_tokens": 30, "cost_usd": 0.25}),
    rec("m3", "2026-10-14T03:00:00.000Z", "failed", "claude", "sonnet",
        {"model": "claude-sonnet-5-5", "input_tokens": 1, "cached_input_tokens": 2, "output_tokens": 3, "cost_usd": 0.5}),
    rec("m4", "2026-10-14T04:00:00.000Z", "succeeded", "claude", "sonnet", None),
    rec("m5", "2026-10-14T05:00:00.000Z", "succeeded", "claude", "haiku",
        {"model": "", "input_tokens": 4, "cached_input_tokens": 5, "output_tokens": 6, "cost_usd": 0.125}),
    rec("m6", "2026-10-14T06:00:00.000Z", "succeeded", "codex", "gpt-x",
        {"input_tokens": 7, "cached_input_tokens": 8, "output_tokens": 9, "cost_usd": None}),
    rec("m7", "2026-10-14T07:00:00.000Z", "error", "gemini", "alpha",
        {"input_tokens": 2, "cached_input_tokens": 2, "output_tokens": 2, "cost_usd": 0.0625}),
]
d = tempfile.mkdtemp()
path = os.path.join(d, "log.jsonl")
with open(path, "w") as fh:

code, out, err = cli_runner("models", path)
print(out)
print(err)
assert code == 0
rows = list(csv.reader(io.StringIO(out)))
header = ["provider", "model", "calls", "failed", "input_tokens", "cached_tokens", "output_tokens", "cost_usd"]
assert rows[0] == header

groups = {}
for r in recs:
    st = r["result"].get("stats") or {}
    key = (r["job"]["llm"], st.get("model") or r["job"]["model"])
    g = groups.setdefault(key, [0, 0, 0, 0, 0, 0.0])
    g[0] += 1
    g[1] += 0 if r["status"] == "succeeded" else 1
    g[2] += st.get("input_tokens") or 0
    g[3] += st.get("cached_input_tokens") or 0
    g[4] += st.get("output_tokens") or 0
    g[5] += st.get("cost_usd") or 0.0
keys = sorted(groups)
body, total = rows[1:-1], rows[-1]
assert len(body) == len(keys)
for row, key in zip(body, keys):
    g = groups[key]
    assert row[0] == key[0] and row[1] == key[1]
    assert [int(x) for x in row[2:7]] == g[:5]
    assert len(row[7].split(".")[1]) == 4
    assert abs(float(row[7]) - g[5]) < 1e-9
assert total[0] == "TOTAL" and total[1] == ""
assert [int(x) for x in total[2:7]] == [sum(groups[k][i] for k in keys) for i in range(5)]
assert len(total[7].split(".")[1]) == 4

# FEATURE: Daily Report

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | The daily report summarizes filtered records per start date and ends with a TOTAL row. |
| Depends On  | FEATURE-SummaryReport.md, FEATURE-DateFilter.md |
| Provides    | ddkstat daily |
| Consumes    | report.FilterTarget, report.FilterDates |

## Questions

- None.

## Purpose

`ddkstat daily <log>` shows how many calls, failures, tokens, and minutes each day used.

## Report Contract

- Header: `date,calls,failed,tokens,minutes`.
- One row per start date (the first 10 characters of `started_at`) that has at least one matching record, ordered ascending. Dates with no matching record do not appear.
- `tokens` is input plus cached plus output tokens, with absent or null counts as zero.
- `minutes` is the group's summed `elapsed_ms` written in tenths of a minute: `t = (ms + 3000) / 6000` in integer division, written as `t / 10`, a `.`, and `t % 10`.
- The last row is `TOTAL` over all filtered records, with minutes computed from the summed milliseconds.
- With no matching record the output is the header and `TOTAL,0,0,0,0.0`.
- A record without `result.stats` still counts as a call with zero tokens and minutes.
- Output is CSV with `\n` line endings; `--target`, `--since`, and `--until` narrow the records first.

## Programmatic Acceptance

=== AC daily-rows-and-total ===
Intent: Daily rows are ascending by date, with tokens and tenth-minute values derived from the fixture records.
Requires: executable=go; scope=test

import csv
import io
import json
import os
import tempfile
from drydock_go import cli_runner

def rec(eid, started, status, stats):
    result = {"returncode": 0, "timed_out": False}
    if stats is not None:
        result["stats"] = stats
    return {"execution_id": eid, "started_at": started, "status": status,
            "job": {"command_name": "build", "target": "T", "llm": "claude", "model": "m"},
            "result": result}

def st(i, c, o, ms):
    return {"input_tokens": i, "cached_input_tokens": c, "output_tokens": o, "elapsed_ms": ms}

recs = [
    rec("d1", "2026-10-16T09:00:00.000Z", "succeeded", st(1, 2, 3, 95000)),
    rec("d2", "2026-10-14T01:00:00.000Z", "succeeded", st(10, 20, 30, 2999)),
    rec("d3", "2026-10-18T01:00:00.000Z", "failed", None),
    rec("d4", "2026-10-14T05:00:00.000Z", "failed", st(4, 5, 6, 3000)),
    rec("d5", "2026-10-16T10:00:00.000Z", "succeeded", st(7, 8, 9, 6000)),
]
d = tempfile.mkdtemp()
path = os.path.join(d, "log.jsonl")
with open(path, "w") as fh:
    fh.write("\n".join(json.dumps(r) for r in recs) + "\n")

def tenths(cell):
    whole, frac = cell.split(".")
    assert len(frac) == 1
    return int(whole) * 10 + int(frac)

def tt(ms):
    return (ms + 3000) // 6000

code, out, err = cli_runner("daily", path)
print(out)
print(err)
assert code == 0
rows = list(csv.reader(io.StringIO(out)))
assert rows[0] == ["date", "calls", "failed", "tokens", "minutes"]
days = {}
for r in recs:
    s = r["result"].get("stats") or {}
    g = days.setdefault(r["started_at"][:10], [0, 0, 0, 0])
    g[0] += 1
    g[1] += 0 if r["status"] == "succeeded" else 1
    g[2] += (s.get("input_tokens") or 0) + (s.get("cached_input_tokens") or 0) + (s.get("output_tokens") or 0)
    g[3] += s.get("elapsed_ms") or 0
dates = sorted(days)
assert [row[0] for row in rows[1:-1]] == dates
for row in rows[1:-1]:
    g = days[row[0]]
    assert [int(row[1]), int(row[2]), int(row[3])] == g[:3]
    assert tenths(row[4]) == tt(g[3])
total = rows[-1]
assert total[0] == "TOTAL"
assert [int(total[1]), int(total[2]), int(total[3])] == [sum(days[k][i] for k in dates) for i in range(3)]
assert tenths(total[4]) == tt(sum(days[k][3] for k in dates))

# FEATURE: Failures Report

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | The failures report lists each filtered record whose status is not succeeded, in start order. |
| Depends On  | FEATURE-SummaryReport.md, FEATURE-ModelAttribution.md, FEATURE-DateFilter.md |
| Provides    | ddkstat failures |
| Consumes    | logread.Record.Model, report.FilterTarget, report.FilterDates |

## Questions

- None.

## Purpose

`ddkstat failures <log>` shows which calls failed, when, and how.

## Report Contract

- Header: `started_at,target,command,model,returncode,timed_out`.
- One row per filtered record whose `status` is not `succeeded`, whatever the status value.
- Rows are ordered by `started_at` ascending, then `execution_id` ascending, by byte value.
- `target` is `job.target`, `command` is `job.command_name`, and `model` is the attributed model (`result.stats.model` when non-empty, otherwise `job.model`).
- `returncode` is the integer, or empty when `result.returncode` is null or absent.
- `timed_out` is `true` or `false`.
- There is no `TOTAL` row. With no failed record the output is the header only.
- Output is CSV with `\n` line endings; `--target`, `--since`, and `--until` narrow the records first.

## Programmatic Acceptance

# FEATURE: Test Entry Point

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | A POSIX-compatible bin/test.sh runs go vet and go test from the application root. |
| Depends On  | FEATURE-CommandsReport.md, FEATURE-TargetsReport.md, FEATURE-ModelsReport.md, FEATURE-DailyReport.md, FEATURE-FailuresReport.md, FEATURE-UsageErrors.md, FEATURE-UnreadableLog.md |
| Provides    | bin/test.sh |
| Consumes    | ddkstat summary, ddkstat commands, ddkstat targets, ddkstat models, ddkstat daily, ddkstat failures |

## Questions

- None.

## Purpose

`bin/test.sh` is the project's single test entry point. It lets an operator or the build prove the application is healthy.

## Behavior

- POSIX `sh` only; no bashisms.
- Changes to the application root (the parent of `bin/`) regardless of the caller's working directory.
- Runs `go vet ./...` and then `go test ./...`, and exits zero only when both pass.
- A failure of either command makes the script exit non-zero.
- The Go test suite covers each report, each filter, each skip rule, and each exit code, using logs the tests write themselves. It never reads `sources/run.sh`.
