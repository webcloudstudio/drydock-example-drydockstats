## Foundation Contract

The published shape of this foundation. It is built before every other foundation: a web server,
a database, or a CLI is built *into* this tree, this environment, and this test runner. Carried
verbatim into `go_compact.md`.

- source_root: internal/
- test_command: go test ./...
- environment: the module declared in `go.mod`; no vendored toolchain
- dependencies: `go.mod`

```
project/
  go.mod                  # module path; the Go toolchain version
  cmd/                    # one directory per binary, each package main
  internal/               # application packages; not importable outside this module
  bin/                    # launchers; each runs the toolchain, never a vendored copy
```

Application foundations add packages under `internal/`. The generated persistence library is a
separate module at `persistence/`, linked by the root `go.mod`.

### Native application layouts and fixtures

Initialize the root `go.mod` in the language foundation before the DATABASE block.
Use `cmd/app/main.go` for process startup, `internal/cli` for CLI behavior, and
`internal/appserver` for HTTP behavior. The root application module requires
`drydock.local/persistence v0.0.0` with `replace drydock.local/persistence => ./persistence`;
the generated persistence directory owns its nested module. Run both module test suites.

For a CLI, expose `Run(args []string, stdout, stderr io.Writer) int`, use a local
`flag.FlagSet` with `flag.ContinueOnError`, and test with `bytes.Buffer`. Only main calls
`os.Exit`. For HTTP, expose `NewHandler(...) http.Handler` using `net/http.ServeMux`.
Use `httptest.NewRecorder` and `httptest.NewRequest` for handler tests, or
`httptest.NewServer` with `t.Cleanup(server.Close)` when testing a real HTTP client.
Keep business logic in application packages and persistence access in the shipped library.

### How do we execute and measure Acceptance Criteria in this language?

An Acceptance Criterion (AC) is an executable check of Blueprint-required behavior. Native tests
use `testing` in `*_test.go`; the project gate is `go test ./...`. Within the existing Blueprint
Python AC container, execute a named test through the shipped helper:

```python
from drydock_go import run_test
result = run_test("./internal/orders", "TestCreateOrder")
assert result.passed, (result.status, result.stdout, result.stderr)
```

Drydock stages this helper beside the criterion. It runs `go test -json -count=1 -run` with an
exact test name, retains output and per-test outcomes, and rejects absent/skipped tests as proof.
The enclosing AC provides identity, timeout, result storage and repair state. Compilation errors
remain distinct from assertion failures in `result.status`. Coverage and persistence observations
require explicit instrumentation per criterion; unavailable observations are unknown.

A criterion that exercises the command line runs the built executable through the same helper,
never `go run`, which reports every non-zero program exit as 1:

```python
from drydock_go import cli_runner
code, out, err = cli_runner("--top", "0", "data.csv")
assert code == 2, (code, out, err)
```

`cli_runner` builds the single `./cmd/<name>` main package once with `go build` and returns
`(exit_code, stdout, stderr)`; pass `package="./cmd/<name>"` when there are several, and `input=`
for standard input. A failed build settles the criterion as `execution-error`.

### How does this language provide the shared persistence contract?

Use the shipped module in `Rigging/languages/go/persistence/`. Drydock copies it to the Target's
`persistence/`, generates `schema.go`, `testing.go` and a schema command from `DATABASE.md`, and
links it into the existing root `go.mod` as `drydock.local/persistence`. Driver versions and sums
are shipped; SQLite uses `go-sqlite3` (a C compiler and CGO are required), PostgreSQL uses `lib/pq`.
Run `go mod download` during dependency provisioning; execution requires these modules available.

Call `persistence.OpenDatabase(ctx, dsn)`, then typed methods such as
`db.Tickets.List(ctx, persistence.TicketsListInput{Status: "open"})`. Methods return a value and
an error. Optional inputs use pointers; read results are generated structs. Undeclared operations
and unsupported field types fail explicitly. Use `OpenSession(ctx, dsn)` for native database criteria;
empty DSN selects the configured, provisioned application store. Defer its cleanup and check the
returned error: it rolls back on success and failure, never applies schema or deletes the store.
Pass the same Store to the feature. Other connections and external effects require committed,
idempotent criteria with owned records and supported cleanup. Both engines retain autocommit
outside explicit rollback scopes.

The Go library and generator are verified on SQLite and PostgreSQL. Keep application SQL inside
the library; agents write callers. The language foundation must create `go.mod` before the
DATABASE step. Python Blueprint AC containers invoke the native Go tests through `run_test`.

# ARCHITECTURE: DrydockStats

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Module layout, package boundaries, shared types, and technical decisions for the ddkstat LLM log reporter. |
| Depends On  | None |
| Provides    | go.mod, cmd/ddkstat, internal/cli, internal/logread, internal/report |

## Purpose

`ddkstat` is a command-line reporter for Drydock's LLM execution log (`logs/llm.jsonl`). It reads a
JSON Lines file, skips malformed and duplicate lines, narrows the records by optional Target and
date filters, and writes one of six CSV reports to standard output. It has no database and no
network access, and it never writes to the log it reads.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`, which remains the decision of record.

| Technology | Where it applies |
|---|---|
| Go 1.22 or newer, standard library only | All application code; no third-party modules |
| `go test` and `go vet` | The test runner behind `bin/test.sh` |
| JSON Lines | The input format, decoded with `encoding/json` |
| POSIX sh | `bin/test.sh` and the supplied grader `sources/run.sh` |

## Module Layout

```text
go.mod                    module declaration, Go 1.22 or newer, no require lines
cmd/ddkstat/main.go       package main; the only caller of os.Exit
internal/cli/             Run, argument parsing, exit codes, usage line
internal/logread/         reading, skip rules, de-duplication, record model
internal/report/          filters, aggregation, and CSV formatting as separate functions
bin/test.sh               POSIX launcher for go vet and go test
```

## Package Boundaries

| Package | Owns | May import |
|---|---|---|
| `cmd/ddkstat` | Process start; passes `os.Args[1:]`, `os.Stdout`, `os.Stderr` to `cli.Run`; exits with its result | `internal/cli` |
| `internal/cli` | Argument parsing, date validation, exit codes, orchestration of read, filter, aggregate, format | `internal/logread`, `internal/report` |
| `internal/logread` | Opening and reading the log, line numbering, skip and duplicate rules, the `Record` model | standard library |
| `internal/report` | Filtering, aggregation per report, minutes and cost formatting, CSV writing | `internal/logread` |

Parsing the log, aggregating, and formatting are separate functions, each unit-tested. Business
logic lives in `internal/logread` and `internal/report`; `internal/cli` only wires them together.

## Shared Types and Interfaces

```go
// internal/logread
type Record struct {
    ExecutionID  string
    StartedAt    string // RFC 3339 UTC; the first 10 characters are the start date
    Status       string
    Command      string // job.command_name
    Target       string // job.target
    Provider     string // job.llm
    Model        string // result.stats.model when non-empty, otherwise job.model
    InputTokens  int64
    CachedTokens int64
    OutputTokens int64
    CostUSD      float64
    ElapsedMS    int64
    ReturnCode   *int // nil when null or absent
    TimedOut     bool
}

func (r Record) Date() string   // StartedAt[:10]
func (r Record) Failed() bool   // Status != "succeeded"

type Result struct {
    Records []Record // kept records in file order
    Skipped int      // skipped lines in the whole file
}

func Read(r io.Reader, warn io.Writer) (Result, error)
func ReadFile(path string, warn io.Writer) (Result, error)
```

```go
// internal/cli
type Options struct {
    Report string
    Target string
    HasTarget bool
    Since  string // YYYY-MM-DD or empty
    Until  string // YYYY-MM-DD or empty
    Log    string
}

func Parse(args []string) (Options, error)
func Run(args []string, stdout, stderr io.Writer) int
```

`Run` uses a local `flag.FlagSet` with `flag.ContinueOnError` or an equivalent hand parser, never
the global flag set, and is tested with `bytes.Buffer`. Report output is buffered and written to
standard output only after the log has been read successfully, so a failing command leaves
standard output empty.

## Execution Flow

parse arguments, open the log, ingest records applying the skip rules, apply the Target and date
filters, compute one report, write CSV. The `skipped` count is computed over the whole file before
any filter applies.

## Shared Output Rules

CSV with one header row and `\n` line endings; minutes written as tenths with
`t = (ms + 3000) / 6000` in integer division and formatted `t/10`, `.`, `t%10`; cost written with
`%.4f`; text ordered by byte value; a `TOTAL` row of zeros when no record matches, where the report
has one.

## Exit Codes

| Code | Meaning |
|---|---|
| 0 | Success, including skipped lines or no matching records |
| 1 | The log cannot be opened or read |
| 2 | Usage error |

Diagnostics go to standard error and are never compared.

## Persistence Ownership

| Boundary | Owner module |
|---|---|
| Persistence, configuration, file stores, external services | None; the application has no database and no external service. The log is read-only input. |

## Technical Decisions

- Records that fail any rule never register their `execution_id`, so a later valid record with that
  id is kept.
- `--help` is an unknown option and exits 2 with the usage line on standard error.
- A repeated option keeps its last occurrence.
- A directory given as the log path is an unreadable log and exits 1.
- A numeric field with a JSON type other than number or `null` counts as zero.

# FEATURE: Command Line

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Parse the ddkstat command line into a report name, the three options, and exactly one trailing log path. |
| Depends On  | ARCHITECTURE.md |
| Provides    | ddkstat <report> [--target <name>] [--since <YYYY-MM-DD>] [--until <YYYY-MM-DD>] <log> |

## Purpose

The command is `ddkstat <report> [--target <name>] [--since <date>] [--until <date>] <log>`. The
report comes first, options follow it, and the log path is last. This feature delivers the
parser and the executable entry point at `./cmd/ddkstat`; date validation, usage-error exit codes,
and unreadable-log handling belong to their own features.

## Behavior

- `<report>` is one of `summary`, `commands`, `targets`, `models`, `daily`, `failures`.
- The accepted options are `--target <name>`, `--since <date>`, and `--until <date>`, each taking
  one value, in any order, between the report and the log path.
- Exactly one log path is the final argument.
- A repeated option keeps its last occurrence.
- `cli.Parse(args []string) (Options, error)` returns the typed `Options` from `ARCHITECTURE.md`,
  and returns a non-nil error for any argument list it cannot accept. `cli.Run` maps that error to
  the usage-error exit code in the usage-errors feature.
- `go build ./cmd/ddkstat` produces the executable using only the standard library.

## Required Unit Tests

The build writes these tests in `internal/cli`, each against real parser output:

| Test | Behavior |
|---|---|
| `TestParseAcceptsEveryReport` | Each of the six report names parses with a log path. |
| `TestParseOptionsFollowReport` | The three options parse in any order and populate `Options`. |
| `TestParseLogPathIsLast` | The final argument becomes `Options.Log`. |
| `TestParseRepeatedOptionLastWins` | A repeated option keeps its last value. |
