# FEATURE: Target Filter

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Keep only records whose job.target equals the --target value exactly, for every report. |
| Depends On  | FEATURE-ModelAttribution.md, FEATURE-CommandLine.md |
| Provides    | report.FilterTarget |
| Consumes    | logread.Record.Model, ddkstat <report> [--target] [--since] [--until] <log> |

## Questions

- None.

## Purpose

`--target <name>` narrows every report to the records whose `job.target` equals `<name>`. The
comparison is exact and case-sensitive, with no trimming and no prefix or pattern matching.

## Behavior

- The filter runs after ingestion (parse, skip, dedupe) and before aggregation, for all six reports.
- A record is kept only when `job.target == name` byte for byte.
- The `skipped` count in `summary` is computed over the whole file and is not affected by the filter.
- When no record matches, each report writes its header and, where it has one, a `TOTAL` row of zeros.
- Without `--target`, no Target filtering happens.
- The filter is a pure function over the record slice (`report.FilterTarget`) and is unit-tested apart from parsing and formatting.

# FEATURE: Date Filter

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Keep only records whose start date falls within the inclusive --since and --until bounds, for every report. |
| Depends On  | FEATURE-TargetFilter.md, FEATURE-DateOptions.md |
| Provides    | report.FilterDates |
| Consumes    | report.FilterTarget, cli date validation |

## Questions

- None.

## Purpose

`--since <date>` and `--until <date>` narrow every report to records whose start date lies on or
after `--since` and on or before `--until`. Both bounds are inclusive and optional.

## Behavior

- A record's start date is the first 10 characters of `started_at`.
- Dates are `YYYY-MM-DD`, so comparison as strings equals chronological comparison.
- The time of day never affects the outcome: a record at `23:59:59.999Z` on the `--until` date is kept.
- `--since` and `--until` may be combined with each other and with `--target`; all conditions must hold.
- A range matching nothing yields a header and, where the report has one, a `TOTAL` row of zeros.
- The `skipped` count in `summary` is whole-file and not affected by the date filter.
- The filter is a pure function over the record slice (`report.FilterDates`), unit-tested apart from parsing and formatting.

## Programmatic Acceptance

# FEATURE: Summary Report

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Write the one-row summary CSV and provide the shared CSV, minutes, and cost formatters. |
| Depends On  | FEATURE-DateFilter.md |
| Provides    | ddkstat summary |
| Consumes    | report.FilterTarget, report.FilterDates, logread.Skipped |

## Questions

- None.

## Purpose

`ddkstat summary <log>` answers how many records, skips, successes, failures, tokens, dollars and
minutes the log holds, after the Target and date filters. This story also defines the formatting
helpers every other report reuses.

## Output

Header, exactly:

```text
records,skipped,succeeded,failed,first,last,input_tokens,cached_tokens,output_tokens,cost_usd,minutes
```

One data row:

- `records` is the count of kept, filtered records. `succeeded` has status `succeeded`; `failed` is every other status.
- `skipped` is the count of skipped lines in the whole file, regardless of filters.
- `first` and `last` are the earliest and latest start dates (`YYYY-MM-DD`) among matching records, empty when none match.
- `input_tokens`, `cached_tokens`, `output_tokens` are sums of `input_tokens`, `cached_input_tokens`, `output_tokens`; absent values count as zero.
- `cost_usd` is the summed `cost_usd` written with `%.4f`.
- `minutes` is the summed `elapsed_ms` as tenths of a minute: `t = (ms + 3000) / 6000` in integer division, written `t/10`, `.`, `t%10`.

## Shared formatting

- CSV has one header row and `\n` line endings, with no `\r`.
- Aggregation and formatting are separate functions: aggregation returns numbers, formatting turns them into text.
- Minutes rounding applies to the group's summed milliseconds, never to per-record values.
- With no matching record: `records` 0, `first` and `last` empty, sums 0, cost `0.0000`, minutes `0.0`.
