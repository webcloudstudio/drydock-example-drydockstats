FEATURE: Duplicate Ids

FieldValue
Version20261026 V1
DescriptionSkip any line whose execution_id already appeared on an earlier kept record, keeping the first occurrence.
Depends OnARCHITECTURE.md, FEATURE-LogReading.md, FEATURE-MalformedLines.md
Provideslogread.Dedupe

Purpose

Drydock may write the same execution twice. This feature makes the reader keep the first occurrence of each execution_id and skip every later repeat, counting it in Result.Skipped and warning on the warning writer with its line number, without failing the run.

Behavior

  • A line is skipped as a duplicate when its execution_id equals that of an earlier kept record.
  • The first occurrence is kept, and later repeats are skipped even when their other fields differ.
  • Only a record that passes every other rule registers its execution_id. A line skipped as

malformed does not register its id, so a later valid record with the same id is kept.

  • Each duplicate writes one warning naming its 1-based line number.
  • Duplicate detection is exact string equality on execution_id.
  • The skipped count includes duplicates and malformed lines together, over the whole file.

Required Unit Tests

The build writes these tests in internal/logread:

TestBehavior
TestDuplicateFirstOccurrenceKeptTwo lines with one id yield one record, the first, and one skipped.
TestDuplicateKeepsFirstEvenWhenFieldsDifferThe kept record carries the first line's field values.
TestSkippedLineDoesNotRegisterIDA malformed line followed by a valid line with the same id keeps the valid line.
TestDuplicateWarnsWithLineNumberEach duplicate produces one warning naming its physical line number.
TestDuplicateCountedWithMalformedDuplicates and malformed lines are both counted in Skipped.

User Acceptance

  • None.

Guardrails

  • The first occurrence of an execution_id is always the one kept.
  • Skipping a duplicate never changes the exit code and never writes to standard output.
  • Standard library only.
