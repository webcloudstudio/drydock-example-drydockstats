FEATURE: Log Reading

FieldValue
Version20261026 V1
DescriptionRead the Drydock JSON Lines log line by line, ignoring blank lines and numbering every line.
Depends OnARCHITECTURE.md
Provideslogread.Read, logread.ReadFile

Purpose

The log is JSON Lines in UTF-8, one JSON object per line. This feature delivers the line reader in internal/logread: it walks the input, discards blank lines, and hands each non-blank line, with its 1-based line number, to the record decoder that the skip-rule features extend.

Behavior

  • logread.Read(r io.Reader, warn io.Writer) (logread.Result, error) reads every line of r.
  • logread.ReadFile(path string, warn io.Writer) (logread.Result, error) opens the file, reads it

with Read, and closes it. It returns a non-nil error when the file cannot be opened or read, including when the path names a directory.

  • A blank line, meaning empty or whitespace only, is ignored and is neither a record nor counted as

skipped.

  • Line numbers are 1-based and count blank lines, so a warning names the physical line.
  • Lines longer than the default bufio.Scanner token limit are read in full.
  • The log file is opened read-only and never written.
  • Each non-blank line is decoded as one JSON object into a logread.Record.

Required Unit Tests

The build writes these tests in internal/logread:

TestBehavior
TestReadIgnoresBlankLinesBlank lines yield no record and no skipped count.
TestReadNumbersEveryLineThe line number used for a warning counts preceding blank lines.
TestReadAcceptsLongLineA valid record line longer than 1 MiB is read as one record.
TestReadFileMissingReadFile on a nonexistent path returns an error.
TestReadFileDirectoryReadFile on a directory returns an error.
TestReadNeverWritesLogAfter ReadFile, the log file bytes and modification time are unchanged.

User Acceptance

  • None.

Guardrails

  • The log is opened read-only and is never written, truncated, or locked for writing.
  • A blank line is never counted as a record or as a skipped line.
  • Standard library only.
